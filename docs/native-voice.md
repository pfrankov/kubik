# Realtime и GPT-Live через OpenClaw

Английский путь покупателя: [настройка речи](buyer/START.html#voice),
[адрес подключения без обязательного домена](buyer/START.html#address),
[запрос агенту для подготовки установки](buyer/START.html#assistant).
OpenClaw поддерживает Classic, Realtime и GPT Live; текущий адаптер Hermes —
Classic через платформу внутри существующего Hermes Gateway; используются его штатные STT/TTS. Realtime/Live в Hermes 0.21.4 недоступны; [прямое подключение](hermes.md).

Эти режимы используют голосовую модель как интерфейс к прежнему агенту.
Содержательные запросы идут через тот же маршрут Кубика, ключ сессии,
выбранную модель и инструменты. Голосовая модель не заменяет модель агента.
Приветствия и короткие реплики GPT-Live может произносить самостоятельно.

## Голосовая модель на Кубике

`Settings → Agent → Voice` показывает `STT`, `Realtime` и `GPT Live`.
Нажмите режим: после подтверждения открываются его модели. Нажатие уже
выбранного режима открывает настройки без повторного сохранения.
Realtime/GPT Live используют одну модель для ввода и речи; STT показывает
раздельные Recognition и Speech. BOOT возвращает на предыдущий уровень.
Недоступные режимы видны с пояснением `Set up on your agent`.
Режим и модели сохраняются только для сопряжённого Кубика, отдельно от
модели/контекста/инструментов агента. Каталоги не вызывают платные API.

## Начальные настройки на сервере

`channels.kubik.voice.mode` задаёт режим для устройства без собственного выбора.
Сохранённый выбор в Voice имеет приоритет и переживает перезапуск Gateway.

| Значение | Голосовой путь | Начало и завершение записи |
|---|---|---|
| `classic` | Настроенные Gateway STT → агент → TTS | KEY; второе нажатие или отпускание удерживаемой кнопки |
| `realtime` | OpenAI, по умолчанию `gpt-realtime-2.1`; управляемая передача текста агенту | KEY или Hi Tessa на Tess; пауза завершает ввод |
| `live` | OpenAI, по умолчанию `gpt-live-1`; нативная делегация агенту | KEY или Hi Tessa у Tess; непрерывный разговор, KEY завершает его |

Таблица показывает значения по умолчанию. Другие модели текущего режима,
которые сообщает установленный SDK, выбираются в Voice после выбора режима.

Например:

```json
{
  "channels": {
    "kubik": {
      "voice": {
        "provider": "openclaw",
        "mode": "realtime",
        "voice": "marin",
        "language": "ru"
      }
    }
  }
}
```

Для нативных режимов нужны актуальные плагин и прошивка, OpenClaw 2026.9.7
и OpenAI Platform API-key auth на Gateway. Ключ не передаётся Кубику.
`openai-http` и `liveTranscription: true` с этими режимами не сочетаются:
конфигурация отклоняется, другой голосовой путь автоматически не выбирается.
`classic` остаётся значением по умолчанию. Codex/OAuth-модель GPT-Live в этот
путь не включена; наличие подписки само по себе не подтверждает Platform-доступ.

### Включение на работающем Gateway

1. Установите прошивку 0.6.2 и свежий архив плагина по разделам 3–4
   [руководства комплекта](KIT.ru.md). Если эта прошивка уже установлена,
   повторная запись не нужна.
   Выполняйте команды на host Gateway от пользователя, которому принадлежит служба.
2. Если OpenAI Platform ещё не настроен, добавьте ключ интерактивно:

   ```sh
   openclaw models auth paste-api-key --provider openai
   ```

   Для отдельного агента добавьте `--agent ID`. Другой поддерживаемый источник —
   `OPENAI_API_KEY` в окружении самой службы Gateway; переменная только в shell
   не меняет уже запущенную службу. Ключ не записывают в команду, логи или прошивку.
3. Выберите один режим одной командой, сохранив остальные настройки голоса:

   ```sh
   openclaw config patch --stdin <<'JSON'
   {"channels":{"kubik":{"voice":{"provider":"openclaw","mode":"realtime","liveTranscription":false,"apiKey":null,"apiKeyFile":null}}}}
   JSON
   ```

   Для GPT-Live замените `realtime` на `live`. Команда одновременно выключает
   потоковое распознавание Classic: оно несовместимо с нативным режимом.
   Patch удаляет прежние `voice.apiKey/apiKeyFile` (если они были у HTTP-провайдера),
   сохраняя голос, язык и остальные поля. Авторизация берётся только из Gateway.
   Схема плагина отклоняет несовместимые значения до сохранения конфигурации.
   Отдельные STT/TTS для нативного разговора не нужны.
4. Работающий Gateway применяет установку плагина и допустимые настройки через
   управляемое обновление. Дождитесь переподключения и проверьте канал:

   ```sh
   openclaw channels status --probe
   ```

   Если Gateway ещё не запущен, запустите установленную службу командой
   `openclaw gateway start` либо вручную `openclaw gateway run`.
   Не перезапускайте работающий Gateway только ради этой настройки.
   При ошибке запуска канала SDK может выполнить восстановление с перезапуском;
   проверьте журнал и исправьте причину, прежде чем повторять изменение.

   В Settings → Agent → Voice выберите нужный режим. Этот статус подтверждает настройки
   SDK и наличие auth, а не доступ аккаунта к модели. Разговор по KEY проверяет
   настоящий провайдер и может быть платным.

Вернуть обычный голосовой путь: `Settings → Agent → Voice → STT`.
Pairing, Wi-Fi и модель сессии не сбрасываются. Изменение серверного значения
по умолчанию не перезаписывает сохранённый выбор устройства.

`voice.language` задаёт язык речи через инструкции голосовой модели, а не язык
распознавания. Произвольный язык транскрипции нативный SDK отдельно не настраивает.
Обычные уведомления используют настроенный Gateway TTS либо текст,
отдельно от нативного разговора.

## Разговор

В Realtime нажмите KEY или скажите Hi Tessa на главном экране Tess, дождитесь
индикации записи и говорите. Пауза около 0,8 с, KEY или отпускание после удержания
завершают ввод. Без речи запись отменяется примерно через 8 с, предел — минута.

В GPT Live KEY или Hi Tessa включает непрерывную передачу звука в открытую
сессию модели. Отдельной отправки записи нет. Паузы и отпускание KEY не закрывают
разговор. Tess показывает `GPT Live`, сначала `Connecting`, затем постоянную
мятную плашку `Listening` и `KEY to end`. Столбики используют уровень микрофона,
персонаж отдельно реагирует на настоящий воспроизводимый голос.
Микрофон продолжает передавать звук во время ответа. Host вычитает акустическое
эхо по синхронному сигналу динамика, захваченному самим Кубиком. Пользователь
может говорить поверх ответа; при перебивании провайдер очищает текущую озвучку,
а микрофон, Live-соединение и контекст агента сохраняются.
KEY, тап, меню, выключение экрана, потеря связи и ошибка завершают Live.
Plush начинает оба режима только кнопкой.

Realtime закрывает микрофон перед передачей ответа в динамик. Громкость от 20
даёт голос; меньшая — текст. `[[show]]` остаётся экранным блоком, эмоции — реакциями
персонажа. Если озвучка срывается после готового ответа агента, его текст остаётся
на экране. При разрыве связи устаревший голос не попадает в новую сессию.

KEY отменяет голос предыдущего хода. Уже принятая работа агента, включая
инструменты, продолжает выполняться и сохраняется в его истории.
Это не команда остановки инструментов. Явная `/stop` по-прежнему управляет
сессией через OpenClaw; экранный выбор модели блокируется во время разговора.

## Границы текущей реализации

В нативных режимах сначала получается полный ответ прежнего агента, затем его
получает голосовая модель. Аудио от неё передаётся Кубику потоково. Генерация агента
и озвучка пока не перекрываются; поэтому название Realtime/Live само по себе
не гарантирует меньшую задержку, особенно при долгих инструментах.

GPT-Live отдаёт непрерывное аудио без публичной границы ответа. Три секунды
без слышимого аудио завершают только сегмент воспроизведения; `played` подтверждает
его конец, не меняя захват. Цифровая тишина не создаёт новые ответы. Поздняя речь
сохраняется в ограниченной очереди. Длинная пауза внутри ответа может разделить
озвучку на сегменты, но не закрывает микрофон или SDK. Весь разговор ограничен
30 минутами, подключение — 10 с, ожидание ответа — 120 с. До готовности SDK очередь
ввода ограничена пятью секундами, вывода — 60 секундами PCM. Таймаут завершает
голосовую связь, принятая работа агента сохраняется.

Live передаёт синхронные MIC1 и аналоговый loopback ES8311 → ES7210 MIC3
(TDM slot 1), по два независимо кодированных IMA-канала в кадре 40 мс.
Host запускает один SpeexDSP 1.2.1 MDF на всю сессию: 24 кГц, блок 20 мс,
хвост 100 мс. Очистка происходит до передачи в SDK; она не выключает микрофон.
WASM занимает 1 МиБ на Live-сессию, не требует native addon. Loopback учитывает
громкость DAC, но не нелинейность усилителя/динамика; качество зависит от
громкости и акустики. Проверки эха должны включать отдельную речь и разговор
поверх динамика. Сборка: `tools/build-echo-wasm.py`, версия Emscripten 3.1.74.

`output_audio_buffer.cleared` от провайдера отменяет только текущий `gen` через
`speak_cancel` / `cancelled`. Запоздалый результат отменённой делегации не
озвучивается. SDK управляет замещением консультаций; принятые инструменты
продолжаются в истории агента. Realtime остаётся разговором по очереди:
микрофон закрывается до ответа, прерывание доступно кнопкой.

Платные ответы, доступ аккаунта к моделям и реальное время до первого звука
не подтверждаются офлайн-проверками. Нативная озвучка может генерироваться
провайдером даже при громкости ниже 20: устройство выводит текст, но это не
означает отсутствия оплаты за аудио.

Технический контракт: [протокол](protocol.md). Другие адаптеры:
[Agent SDK](agent-sdk.md). Приёмка: [проверки](acceptance.md).

## Диагностика пауз речи

Сервер пополняет буфер по подтверждённому воспроизведению, без второго ожидания
по настенным часам. Кубик отправляет подтверждения каждые 100 мс, чтобы короткие
задержки сети не исчерпывали окно отправки. Целые аудиопакеты обрабатываются
из буфера WebSocket SDK без дополнительной копии в heap.
В сети и на устройстве вместе допускается до 800 мс неподтверждённой
речи; большое сетевое запаздывание всё ещё может исчерпать этот запас.
Нативные фрагменты длиной в несколько секунд принимаются в пределах общей
серверной очереди 60 с и разбиваются перед отправкой. Мелкие порции объединяются до 100 мс,
чтобы не расходовать память на множество мелких сетевых отправок.
Неполный пакет ждёт не дольше 100 мс; окончание ответа отправляет остаток сразу.

При завершении, отмене или потере связи сервер пишет одну строку `speech`:
`sourceGapMs` — интервал поступления PCM от провайдера, `sendGapMs` — отправки,
`creditWaitMs` — ожидание подтверждения; `socketMaxBytes` относится только
к локальной очереди WebSocket. `sourceAgeMs`/`sendAgeMs` показывают незавершённую
паузу. На Кубике `speech rx` даёт интервал приёма; `speech played/stopped/lost`
показывает провалы буфера и максимальное время вызова кодека, включая ожидание
планировщика. Сопоставляйте поколения в одной сессии. Эти счётчики не сохраняют
голос или текст и не измеряют загрузку CPU; стабильный FPS не доказывает плавный звук.

## Проверка доступа к голосовым моделям

Обычная приёмка проверяет контракт установленного SDK без платных обращений.
Для отдельной, явно запрошенной проверки на host Gateway скопируйте туда
`tools/check-live-voice.mjs` из исходного репозитория (в комплект инструмент
не входит) и подставьте путь к нему в команде:

```sh
KUBIK_TEST_LIVE=1 node tools/check-live-voice.mjs --live --package /path/to/kubik/package.json --config /path/to/openclaw.json --agent main
```

Команда использует авторизацию SDK и дважды просит произнести «Готово.»:
по одному соединению для Realtime и GPT-Live. Ожидание каждого провайдера
ограничено 25 с, закрытие — 16 с; звук ограничен четырьмя секундами.
Результат показывает подключение и получение слышимого PCM, но не проверяет
микрофон, контекст агента, динамик Кубика или задержку полного разговора.
Не передавайте ключи в аргументах. Эта проверка не запускается обычной приёмкой.

Подсказки Voice/Guide используют выбранный режим: GPT Live предлагает Hi Tessa
или KEY для включения и KEY для завершения. В Realtime/автоматическом Classic
показано «Pause to send»; Classic с ручной фиксацией — «Press again to send».

Во время записи короткая задача считывает DMA, убирает DC и один раз кодирует
IMA ADPCM (485 байт вместо 1922 на 40 мс). Отправитель передаёт эти байты без
повторного кодирования; VAD получает декодированный PCM, как и серверный адаптер.
Во время записи анимация идёт с целевыми 24 кадрами/с; остальные состояния
сохраняют 30. Очередь из 30 кадров (1200 мс) и PCM для VAD занимают 16560 байтов
в существующей рабочей области TLS для Classic/Realtime. Live использует отдельную
очередь из шестнадцати пар (640 мс), 15552 байта без декодирования PCM: TLS и
воспроизведение работают одновременно. Отправитель Live и подтверждения
воспроизведения имеют приоритет 6, приём WebSocket — 7: очередь микрофона
не должна мешать пополнению динамика. SDK сохраняет общий mutex TLS;
заголовок и тело микрофонного пакета объединяются в одну запись TLS.
Вход Live занимает около 24,2 КБ/с. TLS TX ограничен 1024 байтами:
ESP-IDF разбивает более длинные сообщения, а принимающий буфер сохраняет
лимит 16 КБ. Во время разговора резерв 17408 байтов обслуживает входящие
речевые пакеты и полные записи TLS; одновременный TX использует отдельный
фиксированный слот 1536 байтов. Короткий ответ запускается после стартового
окна 600 мс от первых аудиоданных, даже если граница ответа ещё не пришла.
Диагностика провалов учитывает паузы между порциями речи, а не тишину в конце.
Стек отправителя временно занимает 4096 байт LP SRAM (3072 в Live), оставляя основную SRAM
для Wi-Fi. После завершения отправителя стек освобождается, очередь очищается
и возвращает рабочую область TLS для ответа. Если отправка
не успевает, ход отменяется явно. `voice: input` показывает длительность PCM,
время отправки и `dropped` — потерянные миллисекунды RX-очереди DMA; это не измерение
потерь у провайдера. `mic delivery` показывает пик очереди и остаток стека.
Реальная акустическая проверка по KEY: [приёмка](acceptance.md#реальный-голосовой-проход).

Серверный Realtime VAD получает `silenceDurationMs: 800`, согласованное с локальной
паузой: короткая остановка между словами не должна завершаться раньше на сервере.
Параметр определяет длительность тишины, см. [OpenAI Docs](https://developers.openai.com/api/docs/guides/realtime-vad).
