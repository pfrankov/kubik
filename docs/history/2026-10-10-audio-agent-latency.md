# Звук игр Tess и задержка ответа

Проверена текущая рабочая копия от 10 октября 2026 года с новыми физическими
играми Tess. Старые реализации игр не использовались.

## Динамик ESP32-C6

Одноядерный C6: ввод имел приоритет 9, отрисовка 8, динамик 7.
Перестройка точек задерживала задачу динамика дольше 60 мс DMA-запаса.
Динамик теперь имеет приоритет 10; короткое смешивание завершается записью
в I2S, которая уступает CPU. Алгоритмы игр и синтез звуков не менялись.

Одинаковый набор координат касаний, свайпов, бросков и наклонов через обычный
обработчик касаний на установленной прошивке:

| Измерение | До изменения приоритета | Окончательная прошивка |
| --- | ---: | ---: |
| Максимальное время подготовки кадра | 73,820 мс | 3,448 мс |
| Максимальный интервал успешной подачи | 91,189 мс | 20,923 мс |
| Интервалы более 60 мс | 3 | 0 |
| Ошибки записи кодека | 0 | 0 |

Это время по настенным часам, включая вытеснение и ожидание, а не стоимость
одного синтезатора. Интервал записи — индикатор риска голодания; он не измеряет
аналоговый выход или фактический underrun DMA. Число звучащих кадров между
прогонами не сравнивается: игры имеют случайные реакции. Окончательный счётчик
учитывает ненулевой финальный PCM, исключает неуспешные записи и паузу
перед первым звуком после тихого ожидания.

`test-device-tess-games.mjs` проверил щипок, раскрытие, натяжение, бросок,
разбивание, сбор, наклон, ссыпание, характер и шесть изолированных превью Lab.
Проверены приоритет Settings, сохранение сети/уровней/гайда и отсутствие новых
ошибок памяти. Затем `test-device-audio-games.mjs` проверил временные границы
окончательной прошивки. Это USB-образцы штатного сенсорного пути, не ручная
проверка пальцем. Записан звук физического динамика микрофоном компьютера;
отсутствие субъективных дефектов этой записью отдельно не доказано.

## OpenClaw

В Realtime раньше озвучка ждала завершения всей работы агента. Теперь первый
готовый блок передаётся сразу, последующие голосовые ответы выполняются
последовательно. Ожидающие обычные блоки объединяются до 800 символов, не
пересекая смену эмоции. Разрезанные fenced code и экранные директивы остаются
безопасными для речи; сбой провайдера оставляет уже полученный текст на экране.
Отмена голоса не отменяет принятые инструменты. GPT Live сохраняет свой путь.

На сервере OpenClaw 2026.9.8 сессии Telegram и Кубика использовали одну модель
и уровень рассуждений. Исторические вопросы различались, поэтому они не
подтверждают разницу скорости каналов. Добавлены ограниченные монотонные
метки этапов без текстов/аудио. Новых платных запросов не выполнялось;
фактическое сокращение времени разговора с провайдером ещё не измерено.

Плагин установлен штатной командой на сервере 2026.9.8 и применён в Gateway
generation 3 без остановки службы. Явное объявление отсутствия миграций
сняло блокировку проверки Doctor при обновлении. RPC доступен, Kubik подключён;
Telegram и VK работают без ошибок. Конфигурация моделей/каналов, разрешения
плагинов и приватные настройки совпадают с резервной копией. Кубик подключён
по сохранённому Wi-Fi; ключ, адрес, уровни, яркость и гайд сохранены.
После проверки восстановлен погасший экран.
Registry свежий, плагин имеет статус `loaded`, отложенных миграций — ноль.
Manifest и изменённые голосовые модули совпадают с установленным архивом;
хэши модулей в памяти Gateway штатный CLI не предоставляет.

## Приёмка

Host-проверки, браузерные сценарии, 372 теста плагина, линтеры и ограничения
сложности прошли. Обе сборки ESP-IDF 5.5.1, упаковка и 17 шагов чистой установки
с локальными провайдерами на OpenClaw 2026.9.7 прошли. Apple Clang добавлял
SDKSettings.json в зависимости тестового проекта; его sysroot изолирован,
строгие ожидания выбранных исходников сохранены. Записано только приложение
Tess: NVS и ассеты сохранены. Независимые Luna Max проверили обе области.

## Уровень речи после проверки пользователем

Убрано дополнительное цифровое усиление +6 dB: Speech на 100% имеет unity gain,
на 70% — коэффициент 0,49. Ограничитель пиков и Interface не менялись.
Обе сборки, линтеры, тесты уровней/микшера и 17 шагов установки прошли.
На Tess проиграны три локальных восьмисекундных речевых образца: Realtime и
два ответа на одном Live-соединении, полный `played`, пропусков аудио — ноль.
Использован `--audio-profile --paced`; первоначальный прогон с FPS потерял
полную USB-метрику кадров и не прошёл. Изолированная проверка аудио не заменяет
эту метрику; обычный профиль сохраняет её проверку. Ошибка профиля теперь
возвращается сразу, вместо вторичной ошибки ожидания Live.
Новых платных вызовов не было; аналоговый хрип отдельно не измерен.
Сеть, ключ, громкости и режим голоса восстановлены. После прогона отмечены
новые касания и движение устройства; текущая активность пользователя сохранена.
