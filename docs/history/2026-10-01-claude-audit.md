## Unfinished work / evidence to carry forward

1. **Sound direction needs physical confirmation/fix.** The user reported “Звука сейчас вообще нет. Позиция говорящего не влияет…” at 2026-09-30 16:38, then “Направление разговора всё ещё не учитывается…” at 18:21 (`e8…jsonl`). Current `docs/scenarios.md:478,482` explicitly instructs an ear-calibration and says the owner's left/right claps still need verification. Host simulation and a speaker-generated calibration tone do not establish real left/right performance. This matches the current request exactly.
2. **Wi-Fi list is still one saved network.** Current `firmware/main/settings.h:11-26` has one `wifi_ssid`/`wifi_pass`; `settings.c:141-157,262-283` persists one `connection` blob; `wifi.c:138-147` joins only that pair. `setup.c`'s `NETS_MAX`/`wifi_scan()` array is the scan result list, not stored credentials. Multiple saved profiles and same-name replacement therefore remain new implementation work.
3. **Screen-off Wi-Fi behavior differs from the new requirement.** Current `app_runtime.c:67-73` enters doze when dark, but `wifi.c:105-123` only switches to `WIFI_PS_MAX_MODEM` (association and WebSocket stay alive). It does not power Wi-Fi off and probe every 60 s. The new “wake when agent event occurs” requirement needs a persistent/event-replay design across that disconnect; there is no such schedule/API evident in existing protocol docs.
4. **No agent-neutral adapter API or connection wizard exists.** User history consistently describes an OpenClaw channel. Current setup UI calls out “Адрес OpenClaw” (`firmware/main/portal.html:78-85`); kit requires an already-running OpenClaw (`docs/KIT.ru.md:17-34`); wire protocol names the OpenClaw channel (`docs/protocol.md:3-10,316-337`); plugin entry imports `openclaw/plugin-sdk/*` (`openclaw-kubik/src/index.js:1-19`), and the default voice engine requires OpenClaw runtime APIs (`src/engines/openclaw.js:56-77`). There is no documented agent-adapter contract. Generic support/Hermes is a genuinely new scope; keep the existing wire/protocol core separate from per-agent server adapters and make the setup wizard choose/install/configure an adapter.
5. **Portal submit affordance is at the bottom of the form.** `firmware/main/portal.html:66-87` places “Подключить Кубика” after both credential and server fields, with ordinary flow in `:285-312`; the only viewport CSS found is `main` padding and `.go` styling (`:12,:38`). No sticky/keyboard-aware submit handling appeared in the file. The reported on-screen-keyboard blockage is consistent with this layout.
6. **Reset semantics need a decision and real-device verification.** Reset is currently a visible menu tile requiring a second tap (`app_menu.c:99-115`); it clears Wi-Fi/server/preferences but intentionally retains the device key (`settings.c:300-315`, `docs/KIT.ru.md:282`). Thus it preserves the pairing identity and is not a credential/identity wipe. The repo's most recent device notes say `KUBIK_TEST_RESET=1` was **not run** (`docs/scenarios.md:462`). The current ask wants the mechanism sufficiently hidden and fully described; decide whether “all settings” includes the device identity/pairing, then verify the actual hidden gesture and post-reset first-run path.
7. **Performance and memory evidence is mixed; rerun on the current source/device.** The user repeatedly observed animation stutter/tearing (`ab…jsonl`, 2026-09-27 07:31, 19:48, 19:55; 2026-09-28 09:10–10:02).
