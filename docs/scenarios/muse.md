# Muse без отдельного host

Связанные категории: [подключение](setup.md), [разговор](conversation.md),
[сеть и питание](power-network.md), [сброс](maintenance.md).
Руководство: [Muse](../muse.md). Экспериментальная интеграция; сценарии задают
ожидаемое поведение, а не утверждают завершённую облачную проверку.

## MUS-01

Настройка с телефона.

Действие: Пользователь открывает второй QR, выбирает Wi-Fi и Muse, вводит SDK key и нажимает Connect Kubik.
Результат: Страница показывает скрытое поле ключа и следующий шаг в Muse; адрес сервера не нужен. После проверки Wi-Fi и сохранения Кубик перезапускается и предлагает привязку в приложении телефона. Компьютер не требуется.

## MUS-02

Неверный ключ.

Действие: Пользователь вводит неполный ключ Muse и отправляет форму.
Результат: Страница показывает ошибку на шаге агента; запись настроек и перезапуск не происходят.

## MUS-03

Подтверждение аккаунта.

Действие: Пользователь в Muse выбирает Settings → Devices → Developer mode → Add device, выбирает MuseGadget с экрана Кубика и подтверждает KEY после запроса приложения.
Результат: Приложение может передать доступ к аккаунту и Wi-Fi. Без KEY, при ошибке шифрования или устаревшей сессии доступ не сохраняется.

## MUS-04

Ошибка сети при привязке.

Действие: Пользователь выбирает недоступную сеть или вводит неверный пароль в Muse.
Результат: Приложение получает ошибку Wi-Fi, данные аккаунта не записываются; Кубик возвращается к сохранённой сети. Успешная привязка не объявляется.

## MUS-05

Завершение привязки.

Действие: Пользователь завершает подтверждение и выбор доступной сети в Muse.
Результат: Кубик проверяет сеть, сохраняет device credentials и перезапускается. Bluetooth выключен; Muse подключается напрямую по Wi-Fi.

## MUS-06

Разговор и модели.

Действие: Пользователь нажимает KEY, произносит вопрос, завершает запись и затем открывает Agent → Voice.
Результат: Голосовая заметка уходит в Muse, ответ появляется текстом. STT доступен; Realtime/GPT Live недоступны. Recognition/Agent показывают Managed by Muse; другой модели и озвучки в этом пути нет.

## MUS-07

Смена агента и возврат.

Действие: Пользователь в мастере сохраняет OpenClaw/Hermes, затем снова сохраняет Muse с пустым полем SDK key.
Результат: После первого перезапуска Кубик использует host и не запускает Muse, сохраняя его привязку. После возврата используется сохранённый Muse. Новый ключ вместо пустого поля начинает новое сопряжение.
Завершившееся обновление токенов той же привязки сохраняется с текущим выбором
агента; переключение на host не отбрасывает обновлённые tokens и не включает Muse обратно.

## MUS-08

Сон и сброс.

Действие: Пользователь выключает экран или ждёт сна, получает уведомление Muse по активной сессии, затем выполняет подтверждённый полный Reset.
Результат: Сон бесшумен. Для Muse Wi-Fi сохраняется в экономичном режиме; уведомление будит экран. После привязки Bluetooth выключен и его память освобождена. Reset удаляет ключ, credentials и выбор Muse; следующий запуск требует настройки.

## MUS-09

Новый выбор подключения во время привязки.

Действие: Начать привязку в приложении Muse, затем сохранить настройки подключения
на Кубике, пока прежняя привязка ожидает Wi-Fi; повторное сохранение тех же значений
также считается новым выбором.
Результат: Позднее завершение прежней привязки получает отказ. Сохранённые сеть,
адрес host и выбор агента не заменяются, успешная привязка не объявляется.
