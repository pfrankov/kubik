# Обновление, безопасность и сброс

[Все сценарии](README.md). Настройка: [инструкция](../KIT.ru.md).

## MNT-01

Действие: Проверить комплект перед прошивкой.

Результат: Проверка образов подтверждает целостность и версию; повреждённый образ не записывается.

## MNT-02

Действие: Обновить штатным комплектом; при смене разметки или ассетов записать
таблицу, приложение и ассеты вместе, иначе обновить только приложение.

Результат: Сети, адрес, сопряжение, предпочтения и отметка гайда сохраняются.
Старая открытая сеть без сохранённого ключа пароля переносится с пустым паролем;
ошибка чтения пароля не заменяет сохранённые данные и не создаёт открытую сеть.

## MNT-03

Действие: Перезапустить host агента с сохранённым каталогом состояния.
Остановить ещё запускающийся канал OpenClaw, затем запустить его снова.

Результат: Ключ TLS и разрешения устройств сохраняются; Кубик подключается повторно без нового одобрения.
Hermes восстанавливает закрытые права каталога и файлов после копирования
состояния; ошибка записи не заменяет сохранённые данные частичным файлом.
OpenClaw и собственный Agent Host восстанавливают закрытые права очереди
уведомлений, даже когда LAN-слушатель выключен. Повреждённый файл сохраняется
для исправления и не раскрывает содержимое через ошибку запуска.
Собственный Agent Host так же восстанавливает права конфигурации и сопряжений,
сохраняя значения; ссылки вместо файлов отклоняются.
Отменённый запуск OpenClaw не объявляет канал готовым и не запускает новые
проверки cron. Канал останавливается без ошибки; следующий запуск возможен.
Поздний успех отменённого `connect` собственного адаптера после нового `connect` или `close`
отклоняется с `AbortError`; новое подключение остаётся действующим.

## MNT-04

Действие: Отозвать сопряжение или выключить разрешение устройства у агента.

Результат: Устройство теряет доступ; повторные сообщения не обходят отзыв.
OpenClaw повторно проверяет допуск перед принятием подключения и обработкой
управляющих команд. Отказ при переподключении не заменяет рабочую сессию другого
одобренного ключа того же устройства и её голосовые настройки.
Пока есть отложенные уведомления, host проверяет отзыв и без открытых соединений.
После обнаруженного отзыва сообщения для этого ключа удаляются; повторное
одобрение их не возвращает. Ошибка записи очереди не сохраняет доступ открытой сессии.

## MNT-05

Действие: Захотеть пройти обучение заново.

Результат: Settings → Guide повторяет обучение без удаления настроек.

## MNT-06

Действие: Открыть обычное меню.

Результат: Опасный Reset скрыт; повседневные действия не выполняют сброс.

## MNT-07

Действие: Пять раз коснуться процента заряда за четыре секунды.

Результат: Появляется скрытая кнопка Reset; раскрытие само не удаляет данные.

## MNT-08

Действие: Нажать Reset один раз, затем коротко нажать BOOT или не подтверждать три секунды.

Результат: Настройки остаются; действие нужно подтверждать заново.

## MNT-09

Действие: Подтвердить Reset повторным тапом за три секунды.

Результат: Удаляются сети, адрес и доверие к серверу, ключ устройства, предпочтения и прохождение гайда; начинается первичная настройка с персонажем установленной сборки и требуется новое одобрение.

## MNT-10

Действие: Выбрать Power off и подтвердить повторным тапом за три секунды.

Результат: Кубик показывает выключение, гасит экран и снимает питание процессора, экрана и радио.

## MNT-11

Действие: Удерживать PWR две секунды.

Результат: Кубик показывает выключение, гасит экран и снимает питание процессора, экрана и радио. Короткое нажатие PWR его не включает.

## MNT-12

Действие: При зависании удерживать PWR четыре секунды.

Результат: Питание выключается аппаратно. Короткое нажатие PWR его не включает.

## MNT-13

Действие: Просматривать страницу настройки, журналы или экран агента.

Результат: Пароли Wi-Fi и API-ключи провайдеров не раскрываются; ключи провайдеров остаются на host.

## MNT-14

Действие: При снятом питании коротко нажать PWR, затем удерживать PWR около двух секунд.

Результат: Короткое нажатие не включает Кубик. Удержание подаёт питание, и Кубик загружается. KEY, BOOT и касание экрана выключенный Кубик не будят.

## MNT-15

Действие: Открыть Settings → Status, листать страницы свайпом или тапом по вкладкам Network/Device/Agent внизу.

Результат: Каждая страница — карточки: крупная карточка с главным значением и чипом состояния, ниже строки данных; активная вкладка золотая. Network показывает фактическую сеть, IP, шлюз и DNS и кнопку Wi-Fi, открывающую настройку сети (QR); в Settings внизу слева Status, справа Power off (в сервисном режиме между ними Reset); Device — имя, версию, DHCP-имя и Wi-Fi MAC; Agent — состояние, маршрут и адрес сервера. Данные обновляются раз в секунду. Пароли и параметры токена не показываются.

## MNT-16

Действие: Потерять Wi-Fi при открытом Status, затем коротко нажать BOOT.

Результат: Старые IP, шлюз и DNS исчезают; сохранённый SSID помечен Saved network. BOOT возвращает в Settings. Связь с Wi-Fi и агентом показана раздельно; просмотр ничего не перенастраивает.

## MNT-17

Действие: Подключить Кубик к Wi-Fi и открыть Settings → Status → Device.

Результат: DHCP name — kubik-xxxxxx, где суффикс получен из аппаратного MAC и постоянен для устройства; два Кубика имеют разные имена. Wi-Fi MAC — аппаратный адрес устройства. Роутер назначает IP через DHCP; смена IP не меняет MAC и сопряжение с агентом. Для постоянного IP пользователь закрепляет аренду за MAC на роутере.

## MNT-18

Действие: Обновить прошивку со стандартным сохранённым именем «Кубик» и открыть Status → Device.

Результат: Device name — Kubik, DHCP name — уникальное kubik-xxxxxx. Исправленное стандартное имя сохраняется после перезагрузки; произвольное пользовательское имя не меняется.

## MNT-19

Действие: Получить чистую копию репозитория и собрать вариант Tess по README.

Результат: Модель Tessa уже включена, вручную копировать её не требуется. README и NOTICE явно отделяют её неустановленную лицензию от Apache 2.0 проекта; происхождение и контрольная сумма описаны в licenses/Tessa-model-notice.txt.

## MNT-20

Действие: Собрать выбранного персонажа и подготовить комплект. Затем изменить
используемый C/C++-исходник или заголовок в любом локальном компоненте и повторить упаковку.

Результат: Свежая сборка упаковывается. Изменение используемого файла требует
пересборки; изменение файла другого персонажа, не включённого в эту сборку, не мешает упаковке.

## MNT-21

Действие: Попытаться упаковать сборку с отсутствующими, повреждёнными или устаревшими записями зависимостей Ninja.

Результат: Упаковка прекращается с объяснением и требованием пересобрать прошивку;
отсутствие временных `.d`-файлов после успешной сборки само по себе не считается ошибкой.

## MNT-22

Действие: Запустить проверку звука Tess, включая контрольные случаи разового и устойчивого превышения бюджета, границ и несовпадения PCM.

Результат: Журнал указывает буфер и пять повторов того же входа с совпадающим PCM. Приёмка падает,
если медиана повторов не меньше 1000 мкс или превышений больше четырёх; иначе сообщает
о единичном превышении и проходит. Несовпадение PCM — всегда ошибка.

## MNT-23

Действие: Перезапустить Кубик с сохранённым ключом устройства; столкнуться
с ошибкой чтения ключа или повреждением его формата, затем устранить ошибку.

Результат: Ошибка не создаёт другой ключ и не подменяет идентичность устройства.
После успешного чтения прежнего ключа Кубик использует прежнее сопряжение.

## MNT-24

Действие: Запустить приёмку на чистой копии репозитория с холодным кешем ESP-IDF.

Результат: Каждая сборка персонажа имеет предел 20 минут; запрос версии IDF
и списка голосов — 30 секунд; остальные команды — 10 минут.
Компиляция не обрывается на десятой минуте, если укладывается в новый предел.
APT в Ubuntu показывает журнал; обновление индекса и установка ограничены 180 с каждое.
Ошибка или таймаут завершают приёмку с ошибкой. CI на каждой ОС ограничивает
agent/native 30 минутами, build — 50 минутами, lint — 5 минутами.

## MNT-25

Действие: Установить канал командой `openclaw plugins install openclaw-kubik`.

Результат: OpenClaw получает пакет из npm; README пакета полностью на английском.
Архив вручную не скачивается. Автопубликация новой версии разрешена только
после успешной приёмки того же коммита main; уже опубликованная версия с другим
содержимым не перезаписывается.

## MNT-26

Действие: Отправить изменение в GitHub и открыть проверки Acceptance.

Результат: CI проверяет SHA-256 установочного пакета uv; подменённый файл отклоняется до установки. Lint запускается до ESP-IDF. После его успеха проверки агента и веб-страниц,
нативные тесты и обе сборки выполняются параллельно на macOS и Linux. Ошибка этапа
видна сразу; итоговая приёмка и публикация требуют успеха всех этапов. Кеш ускоряет
подготовку и компиляцию, но не пропускает тесты, новые сборки и чистую установку.
Безопасность звука проверяется с санитайзерами; строгий бюджет каждого буфера
проверяется отдельным бинарником без накладных расходов санитайзера.
