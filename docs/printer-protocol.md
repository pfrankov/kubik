# Printer RPC v2

Печать использует существующее подтверждённое соединение Кубика с host.
В `hello` поле `printer:2` обозначает этот контракт, не наличие бумаги.
Отсутствующая или иная версия даёт `printer_unsupported` при вызове инструмента;
голосовая сессия остаётся рабочей. Старого пути печати и другого транспорта нет.

## Запрос

```json
{"t":"printer","rid":"0123456789abcdef0123456789abcdef","action":"status"}
{"t":"printer","rid":"0123456789abcdef0123456789abcdef","action":"print","text":"Список\nМолоко","emoji":[],"width_mm":30,"height_mm":20,"font_mm":3}
{"t":"printer","rid":"0123456789abcdef0123456789abcdef","action":"print","format":"qr","text":"https://example.com/","width_mm":20,"height_mm":20}
```

`rid` — 32 строчных шестнадцатеричных символа. Неизвестные и дублирующиеся поля,
неполный JSON, Unicode NUL и некорректный UTF-8 отклоняются.
`status` не принимает параметров содержимого. `print` требует непустой текст
до 1024 байт; для `qr` — до 256 байт. Из управляющих символов разрешены LF/TAB.
`format` по умолчанию `text`; другие форматы не поддерживаются.
У текста обязателен внутренний массив `emoji`, максимум восемь уникальных
глифов; у `status` и `qr` он запрещён. Модель не передаёт это поле: host заполняет
его из приватного атласа. Формат и границы — [Apple Emoji](printer-emoji.md).
Итоговый JSON не превышает 4096 байт UTF-8; host проверяет это до отправки.

Числа конечны: `width_mm` 1–216, `height_mm` 1–150,
`font_mm` 1,5–8 только для текста. Это границы входа host, а не обещание такой
ширины текущего принтера. Устройство проверяет ширину по своему распознанному
профилю. Отсутствующий размер выбирается автоматически; явный ноль не означает
автоматический режим. Высота задаёт область документа, шрифт — высоту заглавных.
Округление выполняется до целых точек с учётом DPI.

## Ответ

```json
{
  "t":"printer_result",
  "rid":"0123456789abcdef0123456789abcdef",
  "status":"ready",
  "printer":{
    "name":"PeriPage+1234",
    "model":"PeriPage A6+",
    "firmware":"V1.12_304dpi",
    "hardware":"v3.38.21_AY",
    "dpi":304,
    "feed_dpi":225,
    "width_dots":576,
    "printable_width_mm":48.12631578947369,
    "battery_pct":100,
    "charging":null,
    "formats":["text","qr"],
    "max_height_mm":150,
    "media_height_mm":null,
    "size_source":"model_profile"
  }
}
```

`ready` допустим только для `status`. `printer` обязателен для `ready` и `sent`.
Числовые размеры проверяются на конечность, диапазон и согласованность с DPI
головки по X и шагом растровых строк по Y. Для текущего профиля `dpi=304`,
`feed_dpi=225`: масштаб около 74% выбран по напечатанным образцам. Это
эффективная калибровка, а не механический Y-DPI из ответа принтера.
`charging` обязателен и равен `null`: отдельного подтверждённого флага зарядки нет.
Название, firmware и hardware ограничены; неполные или противоречивые параметры
не превращаются в готовый принтер. Источник ширины — профиль, а не датчик рулона.

Успешная передача печати возвращает `status:"sent"`, `outcome:"submitted"`,
тот же `printer` и обязательный `layout`:

```json
{"format":"text","width_dots":359,"height_dots":177,"width_mm":29.995394736842105,"height_mm":19.981333333333335,"font_mm":2.935111111111111}
```

Пример показывает округлённую область 30×20 мм. Размеры `layout` не превышают
профиль, программную высоту задания и запрошенную область с допуском одной точки.
`font_mm` у QR отсутствует. Растровая строка транспорта всё равно имеет полную
ширину головки; пиксели вне области документа белые. Это не длина отрыва бумаги.

Ошибка — `status:"error"` и `code`: `invalid_request`, `printer_busy`,
`printer_not_found`, `printer_ambiguous`, `printer_unsupported`, `printer_failed`,
`printer_disconnected`, `content_does_not_fit` или `unsupported_character`.
У ошибки печати обязателен `outcome:"not_sent"` либо `"unknown"`;
у статуса `outcome` отсутствует. Необязательные сведения `printer`/`layout`
проходят ту же проверку, что и успешный ответ.

Ни ответ BLE, ни `sent` не подтверждают физический отпечаток. Host добавляет
`paperConfirmed:false`. Ошибка после начала передачи не разрешает автоматический
повтор, даже если позже пришёл запоздавший успешный ответ.

Растровые пакеты FF02 используют WRITE_NO_RSP, каждый отдельно, с паузой
20 мс после постановки в стек. ATT не подтверждает каждую такую команду.
Последующий свежий GET заряда с ответом проверяет соединение, но не доказывает
приём всех строк, состояние внутреннего буфера или завершение печати.
До первого RESET устройство проверяет бюджет всей рассчитанной передачи;
недостаток времени даёт `printer_busy/not_sent` без начала печати.

## Владение и завершение

У одного устройства только один текущий запрос. До отправки повторно проверяются
сопряжение, разрешение, точный socket/ключ и маршрут разговора. Новая сессия не
завершает старый запрос. Повтор одного tool-call ID с теми же параметрами получает
прежний результат из ограниченного кэша; изменение параметров даёт конфликт.

Host ждёт освобождения предыдущей озвучки и удерживает выходной голосовой канал
на время Bluetooth-операции. Новый звук ждёт в существующей ограниченной очереди;
непрерывный вход Live и контекст агента не закрываются. Устройство освобождает
радио до ответа `printer_result`. Срок инструмента: статус 20 с, печать 120 с,
включая ожидание голосового канала.

Отмена/таймаут до отправки означают `not_sent`. После отправки caller может
получить `unknown`, но host сохраняет блокировку озвучки и нового printer RPC
до проверенного позднего завершения, закрытия сессии либо аппаратного предела.
Общий предел устройства — 90 с с очисткой; guard host — 95 с от отправки.
Поздний ответ освобождает ресурсы, но не переписывает уже выданный неизвестный исход.

Firmware RX не выполняет BLE и рендер: только проверяет и помещает ограниченное
задание. App tick отправляет не больше одного ответа вне route mutex. Работа
принадлежит исходной сессии; смена маршрута прекращает новые пакеты, не создаёт
очередь для следующего подключения. Никакие тексты не печатаются фоновым поиском.

См. [поведение и пределы](printer.md), [сценарии](scenarios/printer.md).

## Поток изображения Hermes

`hello.printer_image:1` отдельно объявляет приём изображения; `printer:2`
продолжает обозначать текст и QR. Hermes передаёт только результат OpenAI
`image_generate` из текущего доверенного подключения (до 10 минут), без произвольных путей и URL.
Перед стартом host запрашивает профиль и готовит ограниченный PNG как
монохромный растр полной ширины головки с учётом `dpi` и `feed_dpi`.

`printer_image` с `action=start`, `rid`, `head_width`, `width`, `height`
начинает одно задание. После проверки принтера устройство посылает
`printer_image_ready` с `rid` и `offset` следующей строки. Host отвечает
бинарным кадром вида `06 00`, 32 ASCII-байта `rid`, двухбайтовый big-endian
`offset`, один байт числа строк и 1–16 строк по 72 байта. Следующий блок
передаётся только после нового ready. Пропуски, повторы и лишние блоки
завершают задание; `printer_image` с `action=abort` отменяет его. Итог
приходит обычным `printer_result` с `layout.format=image`. Запрос не ставится
в очередь на повтор после сбоя, а выход бумаги не подтверждается.


Для отдельного изображения `hello.printer_preview:1` объявляет цветной
предпросмотр. До `printer_image/start` host посылает кадры `07 00`, 32 ASCII
байта того же `rid`, двухбайтовый big-endian offset и до 896 байт данных.
Всего 8224 байта: 16 цветов RGB565 big-endian и 128×128 четырёхбитных
индексов (старшая тетрада первая). Картинка вписана без обрезки в чёрный фон. Для ограниченной памяти C6
снимок хранится в 64×64; S3 сохраняет 128×128.
Устройство принимает только последовательные блоки текущей сессии и показывает
полный снимок после подтверждения соответствующего старта печати. Окончание,
ошибка, разрыв или ограничение времени освобождают его. Подтверждения и повтора
предпросмотра нет; текст и смешанный документ не используют этот поток.

## Смешанный документ

Hermes принимает упорядоченные блоки текста и подтверждённых image refs, целиком
проверяет их, компонуя PT Sans в реальных координатах профиля. Текст переводится
в чёрно-белые точки с порогом, изображения — отдельно через Floyd–Steinberg.
Документ разбивается по границам строк максимум на четыре растра высотой до
150 мм и передаётся по `printer_image:1` последовательно под одной output lease.
Кубик добавляет поле отрыва к каждой части. Если документ не помещается целиком,
он отклоняется до печати. При частичном или неизвестном исходе возвращаются
числа переданных и общих частей; повтор документа и использованных изображений
блокируется. Подтверждения выхода бумаги нет.
