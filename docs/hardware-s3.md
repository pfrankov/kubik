# Waveshare ESP32-S3-Touch-AMOLED-1.8 V2

Профиль `esp32s3` предназначен только для **Waveshare ESP32-S3-Touch-AMOLED-1.8 V2**:
CO5300 368×448, CST820, ES8311, AXP2101, I2C-expander, flash 16 МБ и PSRAM 8 МБ.
C6 использует прежнюю ESP32-C6-Touch-AMOLED-2.16 480×480.
Оригинальная S3 1.8 с SH8601/FT3168, S3 2.16 и обычные модули ESP32-S3
не поддерживаются этим профилем. Название чипа из esptool не определяет плату.
До записи сверяйте модель и ревизию с маркировкой, заводской прошивкой и BSP.

## Сборка и установка

Используется закреплённый ESP-IDF 5.5.1. Установите инструменты обеих архитектур:

```sh
$IDF_PATH/install.sh esp32c6 esp32s3
. "$IDF_PATH/export.sh"
idf.py -C firmware -B "$PWD/firmware/build-s3" -DIDF_TARGET=esp32s3 -DKUBIK_CHARACTER=TESS build
python3 tools/package-firmware.py --target esp32s3 --character TESS
```

Plush: `build-s3-plush`, `-DKUBIK_CHARACTER=PLUSH`, `--character PLUSH`.
C6 сохраняет каталоги `build`/`build-plush` и target `esp32c6`.
Не меняйте плату или персонажа внутри существующего каталога сборки.
Сборки разных target запускайте последовательно: они используют общий кеш
`managed_components`.
У S3 отдельные sdkconfig и `dependencies.lock.esp32s3`; обычный
`dependencies.lock` закрепляет зависимости C6.

Архивы S3: `kubik-firmware-tess-esp32s3.zip` и
`kubik-firmware-plush-esp32s3.zip`; комплекты — `kubik-kit-tess-esp32s3.zip`
и `kubik-kit-plush-esp32s3.zip`. Архивы без суффикса предназначены для C6.
Проверка и запись из извлечённого архива:

```sh
python flash-device.py --check
python flash-device.py --port /dev/cu.usbmodem101
```

Установщик проверяет хеши и chip образов, не использует `erase_flash`.
Обычное обновление сохраняет NVS. При замене заводской прошивки сначала
сохраните полный образ flash; заводское приложение не является источником
настроек Kubik. API-ключи голосовых провайдеров остаются на host.
Пустые SSID и адрес разрешено оставить до самостоятельной настройки владельцем:
не записывайте фиктивные сети ради USB-проверок.

## Изображение

S3 использует всю панель 368×448. Видимый логический viewport — 480×584:
компоновка Settings, Guide, Status и сцены персонажа учитывает дополнительную
высоту. Масштаб геометрии одинаков по обеим осям: окружности, персонажи и QR
не вытягиваются по вертикали. QR сохраняет максимальную площадь по доступной
ширине, новые строки не отнимают его место.

Касания всей панели преобразуются в координаты viewport, включая верхний и
нижний края и все четыре угла. Внутренний render-буфер округлён по полосам до
480×592; служебные строки ниже 584 не являются видимой областью или зоной касаний.
C6 продолжает использовать квадратный интерфейс и панель 480×480.

## Controls and touch

На S3 только две кнопки: **BOOT** (GPIO0) и **PWR** (AXP2101). Отдельной KEY нет.
Вход 4 expander — активный высокий сигнал PWR, а не кнопка KEY.
Короткий BOOT на подключённом главном экране начинает запись, отправляет её
в Classic или завершает GPT Live. В меню, гайде, настройке, pairing, текстовой
карточке и Skies короткий BOOT возвращает назад или закрывает текущий экран;
долгий BOOT открывает/закрывает Settings.

В Classic на S3 нажмите BOOT, говорите, затем нажмите ещё раз или коснитесь
экрана для отправки; предел — 60 секунд. Удержание с отправкой при отпускании
остаётся способом C6 с KEY, а на S3 удержание BOOT принадлежит Settings.
В Realtime пауза отправляет ввод; в GPT Live пауза не закрывает разговор,
следующий короткий BOOT завершает его. На офлайн-россыпи BOOT по-прежнему
включает/выключает локальную игру. Ручной сон пробуждается PWR или ответом агента.
Три кнопки C6 BOOT/PWR/KEY и их действия сохраняются.

CST820 сообщает **один контакт**. Для прямого входа в Skies удерживайте
любой один угол экрана Tess 1,5 секунды. Нужен непрерывный контакт в углу;
отпускание или выход из него отменяет жест без броска. Один контакт запускает
игру один раз, для повторения нужно отпустить палец. Ограничения по меню,
ответу, сну, персонажу и офлайн-россыпи такие же, как у [жеста C6](scenarios/tess-skies-entry.md). На C6 сохраняется
удержание двух диагонально противоположных углов; второй контакт на S3 недоступен.

## Наклоны и повороты

У S3 1.8 V2 оси QMI8658 повёрнуты относительно портретного экрана:
экранные `(x, y, z) = (-sensor_y, sensor_x, sensor_z)`. Одинаковый поворот
применяется к акселерометру и гироскопу до фильтрации и распознавания движений.
Поэтому наклон, инерция, вращение сцены и подъём используют одну систему осей;
C6 сохраняет прежнюю ориентацию.

Основание — [официальный Gravitysphere](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/main/firmware/brookesia/components/Gravitysphere/Gravitysphere.cpp):
движение по экрану использует `x -= accel_y`, `y += accel_x`; BSP и Kubik
используют нативную портретную ориентацию без перестановки или отражения экрана.
Физически проверяют поочерёдное опускание каждого края: Tess и свободные точки
должны двигаться к опущенному краю, без перестановки лево/низ.

## Аппаратный профиль

| Узел | C6 2.16 | S3 1.8 V2 |
| --- | --- | --- |
| Дисплей | 480×480 | CO5300, 368×448, X gap 16 |
| Видимый логический viewport | 480×480 | 480×584 |
| Touch | CST9217, до двух точек | CST820, одна точка, I2C 0x15 |
| I2C SDA/SCL | 8 / 7 | 15 / 14 |
| QSPI CLK, D0..D3, CS | 0, 1..4, 15 | 11, 4..7, 12 |
| Reset LCD / touch | ALDO3 / GPIO11 | expander 0x20, выходы 0 / 2 |
| Touch INT | 5 | 21 |
| I2S MCLK/BCLK/WS | 19 / 20 / 22 | 16 / 9 / 45 |
| I2S DIN/DOUT | 21 / 23 | 10 / 8 |
| Аудио | ES7210 ADC + ES8311 DAC, 4-slot TDM | ES8311 ADC/DAC, stereo I2S |
| Усилитель | без управляющего GPIO | GPIO46 |
| BOOT / KEY / PWR | 9 / 10 / 18 | GPIO0 / отсутствует / AXP2101 IRQ, sense expander bit 4 |
| Буферы ADPCM и FFT wake | LP SRAM | PSRAM |
| Стек отправки микрофона | LP SRAM | внутренняя SRAM |

QSPI обеих плат — 40 МГц. S3 использует 240 МГц при активном экране,
динамическую частоту и один CPU для существующего порядка задач.
Expander 0x20 управляет reset LCD (0), питанием дисплея (1), reset touch (2)
и SD CS (7); вход PWR sense (4) не должен превращаться в выход.
На S3 нет ES7210: его четырёхслотовую нумерацию нельзя переносить на ES8311.
Наличие цифрового reference не подтверждает акустическое подавление эха.
Ошибка обязательной инициализации кодека завершает загрузку с ошибкой:
готовность устройства не объявляется с отключённым аудио.

Источники: [официальная плата и ревизии](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8),
[распиновка примеров V2](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/main/examples/arduino-v2/libraries/Mylibrary/pin_config.h),
[BSP 1.8](https://components.espressif.com/components/waveshare/esp32_s3_touch_amoled_1_8/versions/2.0.3),
[expander в официальном примере](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.8/blob/main/examples/esp-idf/92_qmi8658_imu/components/board_variant/board_variant.c).

## Границы проверки

`python3 tools/accept.py` собирает обе платы и обоих персонажей.
Программные тесты проверяют профиль платы, вывод и обратное преобразование
касания, обработку ошибок, память и общий протокол. Они не заменяют проверку
на физической плате. Замеры, сделанные для другой модели S3, не подтверждают V2.

USB-проверки используют локального агента без платных API. Для LAN-режима с
пустым адресом нужен TLS-стенд с явно выбранной identity, а не plain WS.
Отсутствие сохранённой Wi-Fi сети не разрешает добавлять тестовую сеть в NVS.
Ассоциация Wi-Fi, радио во сне и доставка через Wi-Fi требуют отдельных проверок
после настройки владельцем. Логи загрузки, FPS и цифровой PCM не подтверждают
видимость изображения, отсутствие tearing, ориентацию наклонов, слышимость
динамика или качество эхоподавления. Фактические результаты фиксируются отдельно.
