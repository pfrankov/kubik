# Принтер Кубика

`kubik_printer` — инструмент OpenClaw для принтера, подключённого к самому
Кубику. Модель передаёт текст; задание идёт по существующему защищённому
соединению агента с устройством. Отдельный адрес принтера, пароль Bluetooth,
команды ESC/POS и системная печать сервера модели не нужны.

Физический принтер и способ его подключения пока не выбраны. Текущая прошивка
отвечает `not_configured`; она не принимает текст в отложенную очередь и
не объявляет его напечатанным. Драйвер конкретного принтера добавляется отдельно.
Готовность интерфейса не подтверждает Bluetooth, подачу бумаги или качество печати.

## Вызов моделью

Инструмент включается в список разрешённых инструментов OpenClaw:

```json
{"tools":{"alsoAllow":["kubik_printer"]}}
```

Добавляйте имя к существующему `alsoAllow`, сохраняя остальные разрешения.
Инструмент доступен в разговоре, пришедшем с Кубика. Он проверяет канал,
учётную запись и маршрут сессии; модель не выбирает чужое устройство.
В обычном чате другого канала этот инструмент не выдаётся.

Проверка подключения принтера:

```json
{"action":"status"}
```

Отправка текста по явной просьбе пользователя:

```json
{"action":"print","text":"Shopping list\nMilk\nBread"}
```

Разрешён непустой текст UTF-8 до 1024 байт, включая русские буквы.
Перенос строки и табуляция разрешены; остальные управляющие символы,
сырые команды принтера, URL и файлы не принимаются. Начальный интерфейс
предназначен для текста, не для изображений и PDF. Возможности шрифтов и
ширина бумаги определятся драйвером выбранного принтера.

## Что означает ответ

- `not_configured`: на Кубике не настроен драйвер принтера; печать не началась.
- `ready`: драйвер сообщил готовность к приёму текста.
- `sent`: драйвер подтвердил передачу задания; это не доказательство выхода бумаги.
- `error`: запрос отклонён или драйвер сообщил об ошибке.

Для отключённого, несопряжённого или неподдерживающего этот протокол Кубика
инструмент возвращает явную ошибку. Текст не сохраняется для печати при следующем
подключении. Одновременно на устройство отправляется не более одного запроса.

При обрыве, отмене или таймауте после отправки результат печати может остаться
неизвестным. Инструмент не повторяет её автоматически. Перед новой попыткой
пользователь проверяет принтер; модель не должна обещать отсутствие первой копии.
Повтор того же вызова не создаёт дополнительную отправку в пределах ограниченного
кэша работающего экземпляра канала: до 64 записей на аккаунт, завершённые
результаты хранятся 10 минут. Неизвестные исходы отправленной печати сохраняются
до остановки или перезагрузки канала; заполненный кэш отклоняет новые задания,
а не забывает такой исход. Перезапуск сервера или перезагрузка плагина не
является гарантией долговременной дедупликации.

## Разработка и проверка

Формат запросов и ответов описан в [протоколе](protocol.md#printer).
Приёмка использует тестовый принтер на настоящем WebSocket-пути для положительного
ответа и проверяет отказ физического Кубика без драйвера. Платный запрос к модели
для этого не требуется. Тестовый принтер не включается в производственную прошивку.

Перед добавлением драйвера нужны модель принтера, тип соединения и его протокол.
Для Bluetooth важно различать BLE GATT и Bluetooth Classic/SPP: поддержку
конкретного принтера нельзя определить по слову «Bluetooth».
ESP32-S3 поддерживает только BLE; Classic/SPP напрямую недоступен, см.
[официальное описание стека](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32s3/api-guides/ble/overview.html).
