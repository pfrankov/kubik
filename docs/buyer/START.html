KUBIK · SETUP

Set up Kubik.

Connect Tess to your own agent.

Your Kubik is already flashed. You need USB-C power, a phone and a 2.4 GHz Wi-Fi password. Muse needs only your phone. OpenClaw and Hermes also need a computer or server that keeps your agent running.

GitHub setup page: https://OWNER.github.io/kubik/ Temporary address — replace before release.

Buttons1. Prepare your agent2. Connect Wi-Fi3. Approve Kubik4. Talk to TessHelp

Know the buttons.

Facing the screen: BOOT on the left, PWR in the middle, KEY on the right.

BOOT
Press to go back one screen. Hold to open or close Settings.
PWR
Press for screen off/on. Hold about two seconds for power off/on.
KEY
Start voice input. How to send depends on the voice mode; see Talk.

1. Prepare your agent.

Choose the setup for your agent. Muse uses your phone. For OpenClaw or Hermes, start on a Mac or Linux computer connected to Kubik’s home network; install your agent, add the Kubik integration and set up voice. Keep this computer awake. Model and speech providers may charge for usage.

Using Muse? Set up with just your phone

Experimental direct Muse support needs no computer or Kubik host. Sign in to the Muse app and create a personal Muse SDK key. Continue straight to Wi-Fi setup; choose Muse and enter the key in the hidden field. You do not need a server address.

After Kubik restarts, return to your phone’s usual Wi-Fi. In Muse, open Settings → Devices → Developer mode → Add device. Choose the MuseGadget shown on Kubik. Allow Bluetooth, press KEY when asked to confirm, then choose Wi-Fi in the app. Bluetooth is built in and turns off after pairing; all later communication uses Wi-Fi.

Press KEY to send a voice note; read the reply on Kubik. This C6 SDK path returns text: speech output, Realtime, GPT Live and model selection are unavailable. Device/cloud pairing is still awaiting physical verification. A personal key is not included in firmware and cannot be embedded in a retail build under SDK-token terms.

Install OpenClaw

  1. Install OpenClaw using the official Getting Started guide and complete its onboarding. The guide opens your dashboard. If you already have a working OpenClaw, keep it.
  2. Send a short text message in the dashboard. Continue when your agent answers.
  3. Keep the Gateway running. Check its service with the command below. If you used a foreground Gateway, follow the official guide to install its background service before closing the terminal.
openclaw gateway status

This release supports OpenClaw from 2026.9.7 up to, but not including, 2027, with Node.js 24.16+ in the 24.x line or 26.1+. The clean installation is checked with 2026.9.7. Windows/WSL and Docker instructions are experimental; they have not been verified on a physical host here.

Using Hermes or another agent?

Hermes: follow the native Hermes setup. It connects directly to its existing Gateway.

Your own adapter: follow the Agent SDK. A custom ESM adapter uses kubik-agent-host.

Continue below: download the integration, configure voice and check the connection address before scanning Kubik.

Download and install the Kubik integration

Get the current software release from GitHub Releases (temporary link). Extract it on the computer running your agent. Software is downloaded separately; no files supplied with the device are required.

OpenClaw installation commands

Open a terminal in the extracted software folder on the computer running OpenClaw. If that computer is a server, copy the downloaded release there first. Keep the .tgz archive packed.

openclaw plugins install ./openclaw-kubik-0.6.2.tgz --force --accept-capabilities

In Windows PowerShell, use .\openclaw-kubik-0.6.2.tgz for the archive path. Use the .tgz from the GitHub release. This package is not installed by name from npm.

openclaw channels add --channel kubik --enable
openclaw channels status --probe

A running Gateway applies this as a managed update. Wait for reconnection. If the installed service is stopped, use openclaw gateway start. Do not restart a working Gateway just for this step.

For the home-network path, allow incoming TCP and UDP 18790 in the computer’s firewall, limited to your local network. Keep the computer awake. Do not forward these ports on your home router.

Allow the connection through your firewall

macOS: when macOS asks whether Node/OpenClaw may accept incoming network connections, choose Allow. If you previously blocked it, open System Settings → Network → Firewall → Options and allow incoming connections for that application.

Ubuntu with UFW: allow the two protocols from your home subnet. The example below uses 192.168.1.0/24; replace it with the actual LAN subnet from your router settings. Do not paste this example unchanged if your network is different.

sudo ufw allow from 192.168.1.0/24 to any port 18790 proto tcp
sudo ufw allow from 192.168.1.0/24 to any port 18790 proto udp

For another Linux firewall, add equivalent LAN-only rules. Keep the firewall enabled. A guest network or router client-isolation setting may still prevent devices from talking to each other.

Ready: channel status includes a LAN address such as lan kubik://192.168.1.5:18790. This checks configuration; the first conversation checks the actual voice providers.

Choose and configure voice

Configure voice providers on the agent computer. After pairing, choose OpenClaw modes and models in Settings → Agent → Voice. For Hermes, configure Classic providers and models in Hermes.

STT
Classic recognition and speech use separate models. Available with OpenClaw and Hermes.
Realtime
Speak, then pause to send. One voice model, through OpenClaw.
GPT Live
Keep a conversation open until KEY. One voice model, through OpenClaw.

Already have working speech? Keep it. Otherwise open the instructions for your agent below. An agent’s text model and your voice model are separate; a ChatGPT subscription alone does not provide speech API access.

OpenClaw: configure Classic STT and TTS

Already working? Keep your speech settings. For a new OpenAI setup, obtain a Platform API key in your OpenAI account. Store it locally; never enter it on Kubik. The following uses the current OpenClaw 2026.9.7 configuration.

1. Store one speech key, then connect both consumers

On the Gateway computer, use the same operating-system account and OpenClaw state as its service. Inspect the channel bindings and identify the agent routed for your Kubik; without an explicit binding, inspect the default route:

openclaw agents list --bindings
openclaw secrets store set KUBIK_OPENAI_API_KEY --kind secret

The second command prompts privately for the Platform key. Do not use a command-line key value. Then run the wizard, replacing AGENT-ID with Kubik's agent:

openclaw secrets configure --agent AGENT-ID

Inspect existing credentials first. In the wizard, create a dedicated OpenAI API-key auth profile for that agent named openai:kubik-audio. Map its key to the team-store secret: source store, provider default, ID KUBIK_OPENAI_API_KEY. Review only those intended targets and apply the plan. Do not replace an OAuth login, other profiles or their order.

Configure the separate TTS credential reference. This works even when a new installation has no TTS provider entry for the wizard to discover. First inspect the dry-run, then apply:

openclaw config set tts.providers.openai.apiKey --ref-source store --ref-provider default --ref-id KUBIK_OPENAI_API_KEY --dry-run
openclaw config set tts.providers.openai.apiKey --ref-source store --ref-provider default --ref-id KUBIK_OPENAI_API_KEY
openclaw secrets reload

The stored key can serve Classic recognition, Classic speech output and native voice. A profile alone does not enable the Classic TTS path: its separate provider reference is necessary. See OpenClaw secrets commands for the wizard and protected store.

2. Add recognition and speech settings

Add this audio entry to tools.media.models, preserving existing entries. Use the exact profile name chosen in the wizard. Enable tools.media.audio.enabled. These are configuration fragments, not commands:

{"tools":{"media":{"audio":{"enabled":true},"models":[
  {"type":"provider","provider":"openai","model":"gpt-4o-transcribe",
   "profile":"openai:kubik-audio","capabilities":["audio"]}
]}}}

Merge these non-secret TTS settings, preserving the new apiKey reference and existing providers. The provider selection is scoped to Kubik:

{"channels":{"kubik":{"tts":{"provider":"openai","providers":{
  "openai":{"model":"gpt-4o-mini-tts","speakerVoice":"marin"}
}}}}}

Use your local config editor or ask your agent to merge these fragments. Never replace an existing models array with this example alone. Review changes before applying them. OpenClaw's audio guide and speech guide describe other providers. Microsoft TTS does not provide Kubik's required PCM output; an already configured PCM-capable provider such as ElevenLabs may be used.

Before a later setup or upgrade, check the model lifecycle note.

3. New setup: use the Gateway voice path

Apply this step for a new Gateway-based setup, or when deliberately switching to native voice. If an existing custom Classic HTTP voice setup works, keep it; this patch changes that route and removes its channel-only key fields.

openclaw config patch --stdin <<'JSON'
{"channels":{"kubik":{"voice":{"provider":"openclaw","mode":"classic","liveTranscription":false,"apiKey":null,"apiKeyFile":null}}}}
JSON
openclaw channels status --probe

A running Gateway applies a managed update. Wait for reconnection; preserve the stored device mode. Setting a key in a new terminal alone does not update a running background service. Complete pairing before selecting models on the device.

OpenClaw: configure Realtime or GPT Live
  1. Add an OpenAI Platform API key using the protected-store and auth-profile steps. Native voice reads the selected agent's OpenAI API-key profiles. For native conversations alone, configure the auth profile; the Classic TTS reference is needed only for Classic speech and spoken notifications.
  2. Use the Gateway voice configuration in step 3 of OpenClaw voice setup. You do not need separate Classic STT/TTS for native conversations. Classic TTS still serves ordinary spoken notifications.
  3. After pairing, hold BOOT for Settings → Agent → Voice. Select Realtime or GPT Live; the model list opens immediately. Choose a model advertised by your server. Your account must have access to it.

For STT mode, Recognition and Speech open their separate model lists. Realtime and GPT Live share one voice model for input and output. Choices persist for this device and pairing identity; they do not change your agent's main model.

A status probe checks settings, not paid-model access. With your consent, try one short conversation after pairing. Volume 20+ and ready TTS give speech; lower volume or missing TTS gives text.

Hermes: connect directly and configure speech

Install the Kubik platform inside the existing Hermes Gateway. No companion host, Agent API server, second computer or SSH tunnel is needed.

  1. Install and configure Hermes on your agent machine. Check a text reply.
  2. Download the Kubik GitHub repository and run this as the Hermes service user, using its Python environment:
python tools/install-hermes.py --home ~/.hermes

Use your actual HERMES_HOME if different. When conversations are idle, restart the existing Gateway:

hermes gateway restart

Configure STT and TTS providers, models and credentials in Hermes itself using its voice guide. Ready STT enables voice input; ready TTS and Speech volume 20+ enable spoken replies. Realtime and GPT Live are unavailable in Hermes 0.21.4. Model changes are made in Hermes, not this device's picker.

Enter kubik://HOST:18793 on Kubik. HOST must be reachable from its Wi-Fi; a public IP works without a domain. Open TCP 18793 on that server as needed. Blank-address discovery is not provided by the Hermes platform.

Approve only the matching code shown on Kubik:

python ~/.hermes/plugins/kubik/pair.py CODE

Keep only Hermes Gateway running. Its plugin handles the device connection, native speech and device conversation.

Check model availability before setting up voice

Model examples match the shipped OpenClaw 2026.9.7 and Kubik integration. OpenAI has deprecated GPT-4o Mini TTS; its listed snapshots retire on 6 January 2027. gpt-4o-transcribe retires on 26 February 2027. Before using this guide after those dates, update the integration and verify compatible replacements against the installed Gateway or host catalog and OpenAI model lifecycle; model availability can change.

Next: check the address below, then connect Kubik’s Wi-Fi.

Check the connection address

On the same home network

  1. Run OpenClaw with its Kubik channel, or Hermes Gateway with its Kubik platform.
  2. Connect Kubik to the same trusted network. Avoid guest networks with client isolation.
  3. For OpenClaw, allow TCP and UDP 18790 on the agent machine and leave Server address blank for discovery. For Hermes, allow TCP 18793 and enter kubik://HOST:18793, using that machine’s LAN IP.

If discovery is blocked

For OpenClaw, run:

openclaw channels status --probe

Copy the complete kubik://… address in the Kubik channel's lan status. For Hermes, enter kubik://HOST:18793 using its machine's IP reachable from Kubik's Wi-Fi. Put it in the phone form.

Example only: kubik://192.168.1.5:18790. Use your own address and actual port. Reserve that computer's LAN address in your router if it changes often. If no reachable address appears, check the listener bind and network first.

Use the Kubik listener: OpenClaw port 18790, Hermes port 18793. Use the device connection address prepared for your selected agent.

OpenClaw on a remote server

This route needs a server IP reachable from your home, plus permission to configure its firewall. Download the software release there and install the Kubik channel there. On that server, inspect existing settings first. Apply the managed update while conversations are idle and follow any CLI apply hint:

openclaw config patch --stdin <<'JSON'
{"channels":{"kubik":{"listen":{"enabled":true,"port":18790,"public":true}}}}
JSON
openclaw channels status --probe
  1. Allow inbound TCP 18790 in the server and hosting-provider firewalls. Restrict it to your home public IP where practical; update that rule if your home IP changes.
  2. Obtain the server's public IPv4 address from your hosting account. Do not use a private LAN or Tailscale address unless your router actually routes Kubik to that network.
  3. Enter kubik://PUBLIC-IP:18790 in the phone form, replacing PUBLIC-IP. Approve only the matching device code on this server.

The channel uses encrypted TLS and device pairing with a pinned server identity. Keep its state directory: replacing that identity requires pairing again. UDP discovery is for the local network; do not open UDP on the internet. Keep the OpenClaw dashboard private.

Already own a domain?

You may use a domain resolving to the server for the direct listener. For a restricted HTTPS tunnel or reverse proxy, follow the deployment guide and expose only /kubik/v1. This is an advanced alternative; it requires your own domain and infrastructure. A generic dashboard link will not work.

Hermes on a remote server

Install the Kubik platform on that same server. Enter kubik://PUBLIC-IP:18793 on Kubik and allow TCP 18793 through its firewall. A domain and a home computer are not required. A Tailscale-only address requires an actual route from Kubik's Wi-Fi; phone Tailscale alone is insufficient.

Keep the existing Hermes Gateway running; no tunnel or companion daemon is needed.

Ready: your agent is running, voice is configured and you know whether to leave Server address blank or enter your prepared address.

2. Connect Kubik to Wi-Fi.

Muse: choose Muse in the agent step and enter your personal SDK key; a server address is not needed. After saving, continue in the Muse app.

  1. Connect USB-C power. Press PWR briefly to wake the screen; if Kubik is powered off, hold it for about two seconds. An unconfigured device shows Scan to join Wi-Fi. Otherwise, hold BOOT for Settings → Wi-Fi.
  2. Scan the first code with your phone and join KUBIK-XXXX. Stay on this network if the phone reports “no internet”.
  3. Wait for the gold title Scan again for setup. Scan the new code to open the setup page. You can also open http://192.168.4.1/ while joined to KUBIK-XXXX.
  4. Select your 2.4 GHz Wi-Fi, enter its password, then tap Continue to agent.
  5. Select the agent you installed. For OpenClaw on the same trusted home network, leave Server address blank. For Hermes, enter kubik://HOST:18793. These choices show instructions; they do not install the agent.
  6. Tap Connect Kubik. It saves the network and restarts. The phone may disconnect; watch the device instead of submitting again.

Ready: Kubik reaches the agent and displays an eight-character pairing code. Wi-Fi success alone does not mean the agent is paired.

3. Approve your Kubik.

Muse: finish pairing in the phone app as described above; no computer command or host code is needed. The steps below apply to OpenClaw/Hermes.

Keep the code on Kubik’s screen visible. Run the following on your own OpenClaw computer:

openclaw pairing list kubik

The code on the screen must be in that list. If it is missing, do not approve anything: use Connection help to check the server address. If a new device shows Connected before your approval, stop and check the connection; this is not the normal first-pairing path.

First OpenClaw device? Check command ownership

When OpenClaw’s commands.ownerAllowFrom list is empty, CLI approval records the first paired identity there. Kubik’s key-bound identity is not a human command owner. If you use a human owner account on another channel, configure that account before approving Kubik. For example, replace the sample Telegram ID with your own:

openclaw config set commands.ownerAllowFrom '["telegram:YOUR_USER_ID"]' --strict-json

If you do not have another channel yet, pairing still works; explicitly configure your human owner when adding one later. See OpenClaw pairing. Before removing the Kubik plugin, remove any kubik:… entries from this owner list so they cannot restrict other channels.

Hermes: approve the displayed code on its machine with python ~/.hermes/plugins/kubik/pair.py CODE.

OpenClaw: approve only a matching code. Replace CODE below with the one on your device:

openclaw pairing approve kubik CODE
A custom adapter

Leave the host running and open another terminal in the downloaded software folder. Use the same host state directory as setup/serve.

npx kubik-agent-host pair-list

Approve only the code matching the device:

npx kubik-agent-host approve CODE

Ready: Kubik shows a welcome and its short guide. No token needs to be copied onto the device.

4. Talk to Tess.

Follow the on-device guide, then return to the home screen with BOOT. Say “Hi Tessa”, then ask a question. You can also use KEY, as shown below.

OpenClaw supports the modes below. Hermes currently supports Classic; configure its providers and models in Hermes.

Voice modeStart and send
ClassicHold KEY, speak, then release. Or press KEY briefly to record, then press it again to send.
RealtimePress KEY, speak, then pause to send.
GPT LivePress KEY or say “Hi Tessa”. Speak naturally, including during replies; KEY ends the conversation. On Tess, “Listening” shows when you can speak.

With available voice output and volume 20 or higher, replies are spoken. Lower volume or unavailable TTS gives text. Tess grows while waiting and responds to the played voice.

Tess: “Hi Tessa” can start a conversation on the lit or dimmed home screen when the agent and voice input are ready. In Classic/Realtime, pause to send. In GPT Live, KEY ends the conversation. Activation is disabled in menus, Guide, setup, pairing, sleep, and while the agent is busy or speaking. The model recognises “Tessa” and can also activate without “Hi”. Plush uses KEY.

Change settings later

  • Hold BOOT: open or close Settings. Press briefly: go back one screen.
  • OpenClaw — Settings → Agent: tap the model tile to change the agent model. Tap Voice to choose STT, Realtime or GPT Live. The selected mode is marked. Tap it to open its models; tap another available mode to switch. BOOT goes back one level.
  • Sound: the main volume slider controls speech. Hold it for 0.8 seconds without moving to open separate Speech and Interface sliders. BOOT returns to Settings. Both levels are saved; muting Interface does not mute your agent.
  • Settings → Status: swipe through current network addresses, DHCP name, MAC and agent endpoint. BOOT returns.
  • Settings → Guide: replay the tour without erasing anything.
  • Press PWR: screen off/on. Hold about two seconds: power off/on.

With OpenClaw, STT has separate Recognition and Speech models. Realtime and GPT-Live share one voice model for both, without changing the agent model. Available choices come from your agent computer and are saved for this paired Kubik. Set up providers and keys on that computer. Modes that need setup are shown but cannot be selected.

Done: your agent responds through Kubik. Keep its computer and service running for future conversations and notifications.

Connection help

The setup page will not open

Scan the current Wi-Fi QR to reconnect to KUBIK-XXXX: its password changes whenever setup is reopened. Accept staying without internet, then open http://192.168.4.1/. Temporarily disable a phone VPN that blocks local access. If Kubik is already connected, open Settings → Wi-Fi to show setup again.

Wi-Fi connects, but there is no pairing code

OpenClaw: check that its Kubik channel is running. Guest Wi-Fi and client isolation can block discovery.

openclaw channels status --probe

Allow local inbound TCP and UDP 18790. If discovery is blocked, follow Connection address: copy the actual Kubik listener’s complete address, including its port. Open Settings → Wi-Fi, enter it in Server address, save and match the new pairing code.

Hermes: keep Hermes Gateway running with its Kubik platform. Enter kubik://HOST:18793 and allow TCP 18793 on that machine. HOST must be reachable from Kubik’s Wi-Fi. Hermes uses this manual address.

The code is missing from OpenClaw’s pairing list

Do not approve another entry. Confirm you are using the intended agent computer. Reopen Settings → Wi-Fi, set its explicit kubik:// LAN address and save. Match the code again. Use automatic discovery only on a network you trust.

My agent is on a remote server or another network

Follow Connection address: direct pinned TLS to OpenClaw port 18790 or to Hermes port 18793. Neither path requires buying a domain. Prepare this before connecting Wi-Fi.

A voice mode says “Set up on your agent”

Check the status in Settings → Agent. In Classic, set up the missing STT or TTS provider on the agent computer. In Realtime or GPT-Live, check native voice configuration and authorisation. Then use Check again in Guide. Without speech input you cannot record a command; without supported voice output you can still read replies. Volume below 20 also selects text. See Voice setup.

No selectable models

A working voice provider may not offer model selection. Check Voice in Agent; an empty list alone does not mean voice is unavailable. Tap Refresh to reload the catalogue after updating the agent configuration. Hermes and custom adapters may keep model selection on the agent computer.

No answer, or a provider error

Try one short request after checking the provider account, quota and network. A ready status confirms settings, not actual access to a paid model. Inspect the Gateway log on your agent computer. Do not send API keys or full private conversations to support.

Add Wi-Fi, check charging or update firmware

Settings → Wi-Fi adds a network. Up to eight networks are remembered; saving the exact same name updates that profile. The home-screen bolt means active charging. In Settings it also means confirmed USB power, including a full battery.

Firmware updates use USB, not Wi-Fi. Install the application and assets from one matching character archive. The firmware download on GitHub contains the flashing instructions; ordinary updates preserve Wi-Fi and pairing. Never erase settings as a routine update step.

Ownership transfer or complete reset

For a tour replay, use Guide instead. A complete reset erases Wi-Fi, server trust, pairing identity and personal settings.

In Settings, tap the battery percentage five times within four seconds. Tap the revealed Reset, then tap it again within three seconds. Kubik restarts into setup and needs approval again. Revoke its old entry on the agent before giving the device to another person.
