# Идеи Muse Gadgets для ESP32-C6

Источник: [Muse Gadget SDK](https://github.com/facebookincubator/muse-gadget-sdk),
изучен commit `693cde9a884ad1edc87251b9f8944815f8de4809`.
Историческое сравнение решений; нативный вариант добавлен отдельно.
Текущая реализация и ограничения описаны в [руководстве Muse](../muse.md).
Облачное сопряжение на физическом Кубике ещё не подтверждено.

## Применено

- **Подтверждение после аппаратного воспроизведения.** В
  [voice_player.c](https://github.com/facebookincubator/muse-gadget-sdk/blob/693cde9a884ad1edc87251b9f8944815f8de4809/esp32/main/voice_player.c)
  плеер завершает ответ после очереди I2S. Кубик уже учитывал аппаратный хвост
  перед сном кодека, но отправлял `played` сразу после опустошения кольца.
  Теперь тот же расчёт 80 мс используется для `played`: последний декодированный
  кадр должен попасть в I2S, затем истечь хвост DMA. Состояние защищено одной
  критической секцией. Отмена и новый ответ не забывают уже смешанный кадр.
  `test-audio-stream.py` проверяет обе границы; `test-speech.py` — отсутствие
  раннего ACK. Реальные Realtime/Live проверяются локальными моками.
- **Частота кварца в простое.** В
  [muse_input.c](https://github.com/facebookincubator/muse-gadget-sdk/blob/693cde9a884ad1edc87251b9f8944815f8de4809/esp32/components/muse/muse_input.c)
  минимальная частота в экономичном режиме равна `CONFIG_XTAL_FREQ`.
  В Кубике нижняя граница теперь 40 МГц, экран удерживает 160 МГц.
  SPI/I2S/Wi-Fi могут повышать частоту своими блокировками. `info.cpu_min_mhz`
  проверяет конфигурацию; `cpu_mhz` — частоту в момент USB-запроса, который
  будит CPU. Временная сборка с `CONFIG_PM_PROFILING=y` выводит через
  `sim/stats` штатную статистику времени в режимах, включая 40 МГц в простое.
  В обычной сборке профилировщик выключен. Частота панели
  остаётся 40 МГц. Без измерителя тока не заявляем процент экономии или
  дополнительное время работы батареи.

## Сохраняем свои решения

- Muse C6 1.8 без PSRAM отдаёт голосовые ответы текстом. У нас другая плата,
  два кодека, потоковый IMA ADPCM, резерв TLS и ограниченный кредит сервера.
  MP3-плеер с большим буфером в PSRAM сюда не переносится.
- Две минуты отключённого Wi-Fi у Muse нарушили бы нашу минутную доставку
  важных событий. Сохраняем свой цикл и подтверждаемую очередь уведомлений.
- Подготовленные DMA-буферы и отдельная задача аудио уже есть; дополнительные
  LVGL, Bluetooth, туннель и SDK Muse для заимствованных идей не требуются.
- Ускорение DHCP отключением проверки занятого IP требует отдельного сетевого
  исследования; настройки сети не менялись.

Связанные документы: [архитектура](README.md), [приёмка](../acceptance.md),
[голос](../native-voice.md), [сеть и питание](../scenarios/power-network.md).


## Прямое подключение: исследование текущего SDK

Повторно изучен официальный SDK, commit
`74a5e2d7fc895f109f83a9a1dbed705dbcd8b1ff`.
Требование: подключаться с ESP32 прямо к Muse, без отдельного Kubik host,
сохранив Tess и существующие пути OpenClaw/Hermes.

- SDK уже поддерживает C6 без PSRAM. Его профиль Waveshare C6 1.8 использует
  `CONFIG_MUSE_HATCH=n`: голосовая заметка отправляется через Muse Link,
  ответ показывается текстом. Плата SDK 368×448 отличается от нашего AMOLED
  480×480; её драйвер панели сюда не переносится.
- Muse использует TLS + WebSocket `/v1/noise` + Noise XX и мультиплексированные
  HTTP-потоки. Это другой протокол, не `/kubik/v1`. На одной сессии работают
  `POST /chat/stream` и `POST /chat/subscribe`. Нельзя добавить только название
  в форму и отправлять туда текущий протокол Кубика.
- SDK token берётся на [странице токенов](https://gadgets.muse.ai/settings/sdk-tokens).
  Он разрешает сопряжение, а не заменяет авторизацию личного Muse.
  Через приложение Muse выдаются device access/refresh tokens; SDK находит VM,
  получает её bearer и обновляет истекающие device credentials.
- Нужны отдельные BLE-сопряжение, хранение и сброс credentials, обновление
  токенов и транспорт Noise. Bluetooth включается только для незавершённого сопряжения Muse.
  SDK требует ESP-IDF 6.0.1; отдельный пробный проект с неизменённым `noise_core`
  успешно собран для ESP32-C6 под 5.5.1. Это проверка компиляции ядра, не
  проверка BLE, облачной авторизации или ответа на физическом Кубике.
- В текущем бинарнике Tess осталось около 45 KiB до границы приложения.
  Перенос SDK требует измерить итоговую flash/RAM и определить безопасное
  обновление, если изменится разметка. Нельзя просто записать больший бинарник
  поверх раздела ассетов.
- Muse сам не озвучивает ответы гаджету в этом пути SDK. Для голоса потребуется
  отдельно определённый TTS; текстовый ответ нельзя выдавать за сохранённую
  возможность озвучки.

Исходники: [C6-путь разговора](https://github.com/facebookincubator/muse-gadget-sdk/blob/74a5e2d7fc895f109f83a9a1dbed705dbcd8b1ff/esp32/components/muse/muse_chat_link.c),
[transport](https://github.com/facebookincubator/muse-gadget-sdk/blob/74a5e2d7fc895f109f83a9a1dbed705dbcd8b1ff/esp32/main/noise_control.cpp),
[сопряжение](https://github.com/facebookincubator/muse-gadget-sdk/blob/74a5e2d7fc895f109f83a9a1dbed705dbcd8b1ff/esp32/main/link_pairing.c).

[Условия SDK token](https://gadgets.muse.ai/sdk-terms) отличаются от Apache-2.0
для исходников: личный token нельзя встраивать в продаваемые устройства.
Проверка доступа и условия распространения необходимы до выпуска варианта Muse;
готовность коммерческого распространения этими исследованиями не подтверждена.
Token не должен попадать в Git, логи, примеры, публичный комплект или тесты.

SDK token пользователя доступен в закрытом локальном файле вне репозитория.
Следующая внешняя проверка — сопряжение в приложении Muse; облачный путь не проверен.
Приложение Tess с нативными компонентами собрано под ESP-IDF 5.5.1; новая разметка
описана в руководстве. Старый замер свободной flash выше относится к сборке до переноса.


## Hermes без отдельного Kubik host

Официальные [Agent API](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server/)
и [голосовой интерфейс](https://hermes-agent.nousresearch.com/docs/user-guide/features/voice-mode/)
дают основу для прямого клиента ESP32. Сервер самого Hermes остаётся необходимым.
На [Agent API `/v1`](https://github.com/NousResearch/hermes-agent/blob/main/gateway/platforms/api_server.py)
порта 8642 объявлено `audio_api: false`: это текстовый путь, не STT/TTS.
[Dashboard audio API](https://github.com/NousResearch/hermes-agent/blob/main/hermes_cli/web_routers/audio.py)
на сервере самого Hermes имеет `/api/audio/transcribe`, `/api/audio/speak`
и `/api/audio/speak-stream`. Его авторизация отличается от `API_SERVER_KEY`;
требуется отдельно проверить контракт удалённого клиента, формат PCM и лимиты.
Эти маршруты описаны как интерфейс Desktop, их стабильность как публичного API
для прошивки не подтверждена. Текущий адаптер Кубика по-прежнему работает
через отдельный host; прямой клиент ещё не реализован.
