# Кубик: руководство по комплекту

Английский путь покупателя: [настройка речи](buyer/START.html#voice),
[адрес подключения без обязательного домена](buyer/START.html#address),
[запрос агенту для подготовки установки](buyer/START.html#assistant).
OpenClaw поддерживает Classic, Realtime и GPT Live; текущий адаптер Hermes —
Classic через платформу внутри существующего Hermes Gateway; используются его штатные STT/TTS. Realtime/Live в Hermes 0.21.4 недоступны; [прямое подключение](hermes.md).

Текущий комплект использует протокол v5: обновляйте host/плагин и прошивку
из одного комплекта. Прежняя версия протокола не подключится; настройки Wi-Fi,
ключ устройства и pairing сохраняются при штатном обновлении приложения.


Кубик — голосовой помощник на столе. Нажмите **KEY** и говорите: в Classic запись отправляется вторым нажатием, а в Realtime также после паузы; GPT Live остаётся включённым до следующего KEY. Агент отвечает голосом или текстом в зависимости от настроек. ПО для установки скачивается с GitHub; этот документ описывает его архив. Читайте по порядку: разделы 2 и 4–6 нужны один раз при установке. Кубик приходит от продавца **уже прошитым**: раздел 3 нужен только для обновления прошивки. Обновления «по воздуху» нет, прошивка обновляется только по USB (раздел 17).

Покупатель начинает с [страницы настройки на GitHub](https://OWNER.github.io/kubik/);
это placeholder, который нужно заменить перед публикацией. Оттуда он скачивает
актуальное ПО; файлы вместе с устройством не требуются. В скачанном архиве
`START.html` содержит копию этой же инструкции, `Getting-started.pdf` — книжку Tess A6.

## 2. Ваш случай

Выберите строку. Одно и то же нужно всем: поставить плагин (раздел 4; прошивка Кубика уже установлена, см. раздел 3 для обновления), подключить Кубик к Wi-Fi (раздел 5) и одобрить код (раздел 6). Строка таблицы говорит, что ещё сделать и что ввести в поле `Agent server address` на странице настройки Кубика.

| Ваш случай | Что сделать | Адрес на Кубике |
|---|---|---|
| **а) OpenClaw на Mac или Linux-компьютере в том же Wi-Fi, что и Кубик** | ничего, кроме разрешения входящих подключений в файрволе (раздел 8); только для домашней сети, которой вы доверяете (см. «Доверие при первом подключении» в разделе 6) | пусто: Кубик найдёт OpenClaw сам |
| **б) Linux-сервер (VPS) с публичным IP, без домена** | `openclaw config set channels.kubik.listen.public true`, открыть 18790/tcp (раздел 9) | `kubik://IP-сервера` |
| **в) Есть свой домен в Cloudflare** | Cloudflare Tunnel на порт Gateway, наружу только путь `/kubik/v1` (раздел 10; постоянный Tunnel из комплекта только для Linux с systemd) | `kubik.example.com` (ваше имя) |
| **г) Tailscale Funnel** | см. предупреждение в разделе 11: публикуется весь Gateway, а не только путь Кубика | `имя.tailnet.ts.net` |
| **д) Windows** | родной Gateway: правило файрвола для TCP и UDP 18790; WSL: `netsh portproxy` (раздел 12); команды Windows не проверялись на реальном компьютере | родной: пусто; WSL: `kubik://IP-Windows` |
| **е) Docker** | опубликовать порт 18790 (tcp и udp), поставить плагин в контейнер (раздел 13; экспериментально, на реальном образе не проверялось) | `kubik://IP-хоста` |

Если Кубик не находит OpenClaw в той же сети (роутер блокирует broadcast, «изоляция клиентов», разные подсети), впишите `kubik://IP-компьютера-с-OpenClaw`.

**Если ни одна строка не подходит.** Когда OpenClaw стоит за домашним роутером без публичного адреса, а своего домена, Tailscale и VPS нет, достучаться до него снаружи домашней сети нельзя: Кубик будет работать только в одной сети с OpenClaw (случай а). Для доступа из других сетей нужен домен в Cloudflare (в), Tailscale (г) или сервер с публичным IP (б).

## 3. Прошивка (обновление и восстановление)

Купленный Кубик уже прошит, этот раздел нужен, чтобы **обновить** прошивку или прошить плату заново. Прошивка идёт только по USB: обновления по Wi-Fi нет. На компьютере с USB-C-кабелем. Нужен Python 3.7 или новее (рекомендуется свежий 3.x; на Debian/Ubuntu ещё `sudo apt install python3-venv`).

Первый переход на нынешнюю разметку требует полной записи штатным скриптом:
Для Tess приложение занимает раздел 0x300000 байт, ассеты начинаются с 0x320000;
для Plush — 0x1E0000 и 0x200000 соответственно. Разметку выбирает сборка персонажа.
Таблица, приложение и ассеты обновляются вместе без стирания NVS/сетей/ключа.
Позднее запись только приложения допустима при той же разметке и ассетах.

Tess использует `firmware/sdkconfig` и `partitions.csv`. Plush при первой сборке
переносит остальные параметры в свой `build-plush/sdkconfig` и использует
`partitions-plush.csv`; дальнейший menuconfig хранится отдельно. На чистой копии
используются обычные `sdkconfig.defaults`. Переключение персонажа требует полного пакета.

1. Распакуйте `kubik-firmware-tess.zip` или `kubik-firmware-plush.zip` в отдельную папку и откройте в ней терминал.
2. Создайте окружение и поставьте esptool (версия важна):
   - macOS/Linux: `python3 -m venv .venv && .venv/bin/python -m pip install esptool==4.12.0`
   - Windows (PowerShell): `py -3 -m venv .venv; .venv\Scripts\python.exe -m pip install esptool==4.12.0`
3. Подключите Кубик кабелем. Проверьте и прошейте (на Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`):

   ```bash
   .venv/bin/python flash-device.py --check
   .venv/bin/python flash-device.py
   ```

   Если подключено несколько плат Espressif, добавьте `--port ИМЯ_ПОРТА`. Первая прошивка занимает несколько минут; не отключайте кабель до конца.

Что нужно знать:

- **Драйверы** на macOS и Windows не нужны: плата подключается встроенным USB-портом чипа (USB Serial/JTAG), а не отдельным мостом CP210x/CH340. Порт называется `COMn` (Windows), `/dev/cu.usbmodem…` (macOS), `/dev/ttyACM0` (Linux).
- **Linux:** нужен доступ к порту. Добавьте себя в группу `dialout` (на Arch — `uucp`): `sudo usermod -a -G dialout $USER`, затем выйдите из системы и войдите снова. Если порт занят, остановите `ModemManager`.
- **Не отвечает загрузчик** (esptool видит режим DOWNLOAD, но синхронизации нет): закройте программы, использующие порт, полностью отсоедините USB-C; при установленной батарее удерживайте **PWR** до выключения, затем удерживайте **PWR** около 2 с для включения; подключите кабель и повторите команду.
- **Экран не запустился после успешной прошивки:** повторите тот же порядок перезапуска (отсоединить кабель, удержание **PWR** при батарее).
- Прошивка не стирает сохранённые настройки; раздел «Сброс» ниже.

## 4. Установка плагина на компьютер с OpenClaw

Плагин ставится **там же, где работает OpenClaw** (для Docker см. раздел 13). Пакет не опубликован в npm, поэтому команда `openclaw plugins install openclaw-kubik` не подойдёт: ставьте файл `openclaw-kubik-0.6.2.tgz` из комплекта, не распаковывая его. OpenClaw принимает путь к файлу прямо в команде установки, поэтому копировать файл в определённое место не нужно. При установке OpenClaw скачивает зависимость плагина (`ws`) из npm, поэтому нужен доступ в интернет.

Если OpenClaw на этом же компьютере, откройте терминал в папке с файлом.

macOS и Linux:

```bash
openclaw plugins install ./openclaw-kubik-0.6.2.tgz --force --accept-capabilities
```

Windows (PowerShell):

```powershell
openclaw plugins install .\openclaw-kubik-0.6.2.tgz --force --accept-capabilities
```

Если OpenClaw на другом компьютере, сначала скопируйте туда файл любым способом (флешка, общая папка, `scp openclaw-kubik-0.6.2.tgz user@OPENCLAW_HOST:`), затем выполните ту же команду на нём, указав путь к скопированному файлу вместо `./openclaw-kubik-0.6.2.tgz`.

Затем на компьютере с OpenClaw (одинаково на всех системах):

```bash
openclaw channels add --channel kubik --enable
openclaw channels status --probe
```

Работающий Gateway применяет установку и включение канала через управляемое обновление; дождитесь переподключения. Если Gateway не запущен, используйте `openclaw gateway start` для установленной службы или `openclaw gateway run` для ручного запуска. Статус должен показать строку вида `lan 192.168.1.5:18790 spki:…; route /kubik/v1`. Эта проверка видит только наличие распознавания и озвучивания, а не работу их провайдера: это покажет реальный голосовой ход (раздел 7). Голосовой движок по умолчанию берёт распознавание из `tools.media.models` (или по ключу провайдера) и озвучивание из `tts.provider` вашего OpenClaw; отдельный аккаунт OpenAI не нужен.

Если ваш случай — б, в, г, д или е, выполните также шаги из соответствующего раздела ниже.

Tess — вариант прошивки по умолчанию. Для Plush выберите комплект `kubik-kit-plush.zip`; для Tess — `kubik-kit-tess.zip`. Персонаж фиксирован сборкой, в Settings переключателя нет. Устанавливайте приложение вместе с ассетами из одного архива. Полный сброс сохраняет вариант прошивки, обычная установка сохраняет сеть и сопряжение.
На основном экране мятная молния появляется только при активной зарядке. В Settings она обозначает подключённое USB-питание, в том числе при 100% после окончания зарядки; процент заряда доступен там всегда.

## 5. Подключение Кубика к Wi-Fi

1. Включите Кубик. QR «Scan to join Wi-Fi» подключает телефон к сети `KUBIK-XXXX`. После подключения заголовок становится золотым и меняется на «Scan again for setup»: отсканируйте второй QR, чтобы открыть страницу настройки. Вручную: `http://192.168.4.1/`.
2. На английской странице с Tess выберите сеть 2,4 ГГц, введите пароль и нажмите **Continue to agent**. При открытой клавиатуре кнопка остаётся доступной.
3. Выберите инструкцию **OpenClaw**, **Hermes** или **Another agent**. Это подсказки по установке интеграции на сервере агента. При необходимости откройте **Server address · optional** и введите адрес из таблицы; пустой адрес включает локальный поиск OpenClaw; для Hermes обязательно `kubik://ХОСТ:18793`. **Change** возвращает к Wi-Fi с сохранением ввода.
4. Нажмите **Connect Kubik**. Ошибка возвращает к форме с сохранёнными полями. «Wi-Fi connected. Next: pairing.» означает подключение к сети; код на самом Кубике означает, что ответил host агента. Одобрите его по инструкции ниже или через независимый host (раздел 17). Если телефон потерял сеть настройки, следуйте экрану Кубика: повторно отправлять форму вслепую не нужно.

Повторное сохранение настроек на этой странице сбрасывает закреплённый ключ сервера (см. «Server key changed» ниже).

## 6. Сопряжение: одобрить код

Когда Кубик дозвонился до OpenClaw, на экране появится `PAIR WITH AGENT` и код из 8 символов. На компьютере с OpenClaw:

```bash
openclaw pairing list kubik
openclaw pairing approve kubik ABCD2345
```

Вместо `ABCD2345` подставьте код с экрана (он должен присутствовать в списке `pairing list`; если такого кода в списке нет, **не подтверждайте** и повторите раздел 5: возможно, Кубик подключился не к вашему OpenClaw). Токен копировать не нужно: Кубик сам создаёт закрытый ключ, сервер запоминает открытый.

Подтверждённый Кубик получает приветствие в течение пары секунд. Запрос действует час; если его не подтвердить за 10 минут, Кубик переподключится и покажет тот же код.

**Доверие при первом подключении (случай а).** Без адреса Кубик ищет OpenClaw широковещательным запросом по Wi-Fi и при первом подключении запоминает ключ того, кто ответил. В сети, где есть чужие или заражённые устройства, ответить может не ваш OpenClaw. Защита здесь одна: сверка кода. Главный признак подмены: Кубик сразу показал `Connected`, хотя вы ещё не одобряли код, — значит, ответил не ваш OpenClaw; в этом случае сделайте сброс (раздел 17) и впишите адрес вручную. Одобряйте только код, который показывает `openclaw pairing list kubik` на вашем компьютере. Если на экране Кубика код, которого нет в `pairing list`, не подтверждайте, впишите адрес компьютера вручную (`kubik://IP-компьютера-с-OpenClaw`) и сохраните настройки заново. Это не заменяет доверия к домашней сети: в общей, гостевой или офисной сети используйте случай в.

**Первое одобрение записывает владельца команд.** Если список `commands.ownerAllowFrom` (владельцы команд OpenClaw) пуст, OpenClaw при первом одобрении через командную строку сам записывает в него `kubik:<идентификатор>:<отпечаток ключа>`. Что это значит:

- канал `kubik` перезапускается: Кубик на секунду отключится и подключится сам;
- Кубик владельцем команд не становится: записи с отпечатком ключа никогда не совпадают с ним;
- на других каналах (Telegram и т. п.) права команд не меняются, пока плагин установлен и включён: OpenClaw пропускает записи чужого канала (проверено на OpenClaw 2026.9.3);
- список перестаёт быть пустым: OpenClaw больше не назначит владельцем того, кого вы одобрите следующим (например, свой аккаунт Telegram), а совет `openclaw doctor` про отсутствие владельца пропадёт. Если хотите быть владельцем сами, задайте список **до** одобрения Кубика. Формат записи `канал:идентификатор`, например для Telegram:

  ```bash
  openclaw config set commands.ownerAllowFrom '["telegram:123456789"]' --strict-json
  ```

- если вы удалите или отключите плагин, удалите из списка записи `kubik:…`: без плагина OpenClaw не узнаёт префикс `kubik`, и на остальных каналах слэш-команды перестанут выполняться, кроме сброса сессии. Команды: раздел 17, «Удаление».

## 7. Проверка голоса

После одобрения Кубик покажет короткий гайд на английском: как говорить через
KEY, какой вывод доступен и где настраивать агента. Он учитывает возможности
текущего режима: STT/TTS в Classic либо нативный голос в Realtime/GPT-Live.
Готовые функции не нужно задавать заново. Без распознавания голосовой ввод
недоступен; без озвучки ответы появляются текстом.
Если озвучка настроена, громкость от 20 включает голосовые ответы, ниже — текст.
Недостающие провайдеры настраиваются на сервере, затем можно нажать `Check again`.
Повторить гайд: удерживать BOOT → `Guide`. Это не сбрасывает сеть и сопряжение.

В Classic нажмите **KEY**, скажите фразу и нажмите **KEY** ещё раз; в Realtime
можно дождаться паузы. В GPT Live KEY включает разговор, следующий KEY завершает его. При доступной озвучке и громкости от 20 услышите ответ,
иначе прочитаете его. Если ответа нет, проверьте Voice в Settings → Agent.
Для Classic проверьте на host `tools.media.models` (или ключ распознавания)
и `tts.provider`; для Realtime/GPT-Live — [настройку нативного голоса](native-voice.md).
Уведомление с компьютера:

```bash
openclaw message send --channel kubik --target kubik-xxxxxx -m "Привет!"
```

`kubik-xxxxxx` — идентификатор Кубика (см. «Отзыв устройства»).

## 8. Файрвол на компьютере с OpenClaw (случай а, Mac/Linux)

Кубик подключается к порту **18790**: TCP для разговора и UDP для поиска OpenClaw в сети. Разрешите входящие соединения:

- **macOS:** при первом запуске появится вопрос «Принимать входящие подключения для node?»: нажмите «Разрешить». Или командой (замените путь на результат `command -v node`, если Node установлен иначе): `sudo /usr/libexec/ApplicationFirewall/socketfilterfw --add "$(command -v node)" --unblockapp "$(command -v node)"`.
- **Linux, ufw:** `sudo ufw allow from 192.168.1.0/24 to any port 18790` (подставьте вашу подсеть; правило действует и для TCP, и для UDP).
- **Linux, firewalld:** `sudo firewall-cmd --permanent --add-port=18790/tcp --add-port=18790/udp && sudo firewall-cmd --reload`
- **Windows** (PowerShell от администратора): `New-NetFirewallRule -DisplayName "Kubik" -Direction Inbound -Protocol TCP -LocalPort 18790 -Action Allow -Profile Private`, то же с `-Protocol UDP`. Если Windows считает вашу сеть «Общедоступной», смените профиль сети на «Частная».

В интернет порт 18790 на роутере **не пробрасывайте**: в обычном режиме он обслуживает только адреса домашней сети.

## 9. Случай б: VPS с публичным IP, без домена

У сервера должен быть публичный IPv4-адрес, но домен не нужен. Здесь Кубик подключается не по Wi-Fi-обнаружению, а по IP.

```bash
openclaw config set channels.kubik.listen.enabled true
openclaw config set channels.kubik.listen.public true
openclaw gateway restart
```

Откройте **только** 18790/tcp: `sudo ufw allow OpenSSH && sudo ufw allow 18790/tcp && sudo ufw enable` (не забудьте открыть порт и в панели хостинга, если там есть свой файрвол; порт Gateway 18789 наружу не открывайте). На странице настройки Кубика введите `kubik://IP-сервера`. В статусе (`openclaw channels status --probe`) должно быть `lan … public spki:…`.

**Что это значит для безопасности.**
- Разговор идёт по TLS с ключом сервера, который Кубик **запоминает при первом подключении** (так называемое «доверие при первом обращении»). Если в момент самого первого подключения злоумышленник сидит на пути между Кубиком и сервером, он может подсунуть свой ключ. Это единственное окно: после запоминания подмена невозможна, Кубик покажет «Server key changed». Прямая пересылка на настоящий сервер не сработает: подпись Кубика привязана к ключу, который он видел, и настоящий сервер её отклонит.
- Как заметить подмену: одобряйте только код, который показывает `openclaw pairing list kubik`. Если Кубик показал код, а такого запроса в списке нет, не подтверждайте и повторите подключение из другой сети.
- Любой в интернете может открыть порт 18790, но без одобренного ключа не получит ничего: ожидающих подтверждения устройств не больше 4 (2 с одного адреса), соединений до допуска не больше 16 (4 с одного адреса), на рукопожатие и запрос уходит не больше 10 с. Атака может лишь занять эти слоты и помешать вам подключить новое устройство, но не подключить чужое.
- Обнаружение по UDP остаётся только для домашних сетей: с публичных адресов на него нет ответа.
- Открывайте наружу только 18790/tcp. Если домашний IP постоянный, ограничьте порт им: `sudo ufw allow from ВАШ_IP to any port 18790 proto tcp`.

## 10. Случай в: свой домен, Cloudflare Tunnel

Нужен домен в Cloudflare и хост OpenClaw под Linux с systemd: постоянный Tunnel из комплекта (`install-systemd.sh`) работает только там. На macOS и Windows этот вариант вручную и официально не поддерживается: комплект там Tunnel не ставит и не проверялся, у Cloudflare есть собственная команда установки службы `cloudflared service install`, но токен при ней остаётся в параметрах службы. Tunnel открывает исходящее соединение, поэтому порты на роутере не нужны. Он направляется на порт Gateway (18789) и публикует **только** путь `/kubik/v1`, остальной OpenClaw остаётся закрытым. Пошаговая инструкция с указанием, где выполняется каждая команда: [`deploy/cloudflared/README.md`](../deploy/cloudflared/README.md). Адрес на Кубике: `kubik.example.com` (страница настройки сама превратит его в `wss://…/kubik/v1`). Проверить адрес до ввода: `node deploy/cloudflared/probe.mjs wss://kubik.example.com/kubik/v1`.

Подпись Кубика из текущего комплекта 0.6.2 включает имя `kubik.example.com`, а плагин сверяет его с заголовком `Host` пришедшего запроса. Не задавайте в приложении Tunnel параметр **HTTP Host Header**: если `Host` заменён, Кубик получит отказ `unauthorized` (в журнале Gateway `transport binding mismatch … this request arrived on host`). Подробности: `deploy/cloudflared/README.md`, шаг 5.

## 11. Случай г: Tailscale Funnel

Внимание, у этого варианта есть цена:
- Funnel **публикует в интернет весь Gateway** (Control UI и WebSocket), а не только путь Кубика `/kubik/v1`. Ограничить публикацию одним путём нельзя: защищают Gateway только пароль и ключ устройства.
- Funnel не запускается без пароля: нужно `gateway.auth.mode: "password"` (лучше через переменную `OPENCLAW_GATEWAY_PASSWORD`).
- Нужны Tailscale 1.38.3+, MagicDNS, HTTPS и разрешение Funnel для узла; порты только 443, 8443 или 10000.

Если это вас устраивает: `openclaw gateway --tailscale funnel --auth password`, а на Кубике адрес `имя-машины.tailnet.ts.net`. Если нужен только Кубик, надёжнее вариант в или б. Режим `serve` не подходит: он открыт только участникам tailnet, а Кубик в нём не состоит.

## 12. Случай д: Windows

- **Gateway на самом Windows:** откройте в файрволе TCP и UDP 18790 (команды в разделе 8). Поле адреса на Кубике оставьте пустым.
- **Gateway в WSL2:** WSL находится за виртуальной сетью, broadcast в неё не попадает, поэтому нужны IP и проброс порта. В PowerShell от администратора:

  ```powershell
  $WslIp = (wsl hostname -I).Trim().Split(" ")[0]
  netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=18790 connectaddress=$WslIp connectport=18790
  New-NetFirewallRule -DisplayName "Kubik" -Direction Inbound -Protocol TCP -LocalPort 18790 -Action Allow -Profile Private
  ```

  На Кубике введите `kubik://IP-компьютера-с-Windows` (адрес в вашей Wi-Fi-сети, `ipconfig`). IP внутри WSL меняется после перезапуска: повторите команду `netsh` с новым `$WslIp`.

## 13. Случай е: Docker

**Экспериментально.** Команды сверены с документацией OpenClaw по Docker (compose-файл с сервисами `openclaw-gateway` и `openclaw-cli`), но на реальном образе не запускались: проверяйте каждый шаг.

Порт 18790 нужно опубликовать в **обоих** протоколах. В `docker-compose.override.yml` рядом с compose-файлом OpenClaw:

```yaml
services:
  openclaw-gateway:
    ports:
      - "18790:18790/tcp"
      - "18790:18790/udp"
```

(на Linux можно вместо этого `network_mode: host`). Broadcast через мост Docker не проходит, поэтому на Кубике вводите `kubik://IP-хоста-Docker`. За мостом Docker адреса клиентов могут выглядеть как внутренний адрес Docker: фильтр «только домашние адреса» там не защищает, ограничьте порт файрволом хоста.

Плагин ставится в контейнер командой `openclaw-cli`. Контейнер `openclaw-gateway` должен быть уже запущен (`docker compose up -d openclaw-gateway`): `openclaw-cli` использует его сеть. Файл нужно положить в каталог, смонтированный как `/home/node/.openclaw`, ниже `OPENCLAW_CONFIG_DIR` — путь на хосте:

```bash
cp openclaw-kubik-0.6.2.tgz "$OPENCLAW_CONFIG_DIR/"
docker compose run --rm openclaw-cli plugins install /home/node/.openclaw/openclaw-kubik-0.6.2.tgz --force --accept-capabilities
docker compose run --rm openclaw-cli channels add --channel kubik --enable
docker compose restart openclaw-gateway
```

Остальные команды из этого руководства с префиксом `openclaw` выполняйте так же: `docker compose run --rm openclaw-cli …`. Каталог должен принадлежать пользователю `node` (uid 1000): `sudo chown -R 1000:1000 "$OPENCLAW_CONFIG_DIR"`. Установка плагина скачивает зависимость из npm: в Docker Desktop это иногда падает с ошибкой DNS (`EAI_AGAIN`), тогда см. раздел «Docker Desktop DNS failures» в документации OpenClaw по Docker.

### Настроения Tess

У Tess бывает настроение, и его видно по цвету, по тому, как она держится и как себя ведёт, и слышно по короткому звуку. Любопытная (зелёная) приглядывается, когда её потрогали. Игривая (янтарная) быстро вертится и зовёт играть. Влюблённая (розовая) ластится, если её долго гладить. Испуганная (фиолетовая) замирает и дрожит от сильной встряски. Ворчливая (красная) отворачивается, если её без конца тыкать. Грустная (синяя) никнет, когда её долго не замечают или пропала связь. Сонная (тусклая серо-лиловая) бесшумно дремлет, когда Кубик давно без дела. Автоматическое затемнение и сон экрана также бесшумны. Если какое-то время ничего не происходит, Tess сама успокаивается и снова становится обычной, примерно за полминуты. Во время разговора звуки настроения молчат. Plush так не умеет. Настроения ничего не отправляют по сети и не запоминаются после выключения. При ожидании Tess плавно приближается; во время ответа остаётся крупной, пульсирует, чуть теплеет и вращается в 4D по воспроизводимому голосу, затем возвращается к покою.

## 15. Кнопки и меню

В Realtime пауза завершает запись, даже если KEY ещё удерживается.
В GPT Live KEY или Hi Tessa включает разговор до следующего KEY; отпускание и
пауза его не закрывают. На Tess `Listening` означает непрерывную передачу микрофона, в том числе во
время ответа. Host вычитает эхо динамика по синхронному каналу loopback. Меню, сон, потеря связи или ошибка завершают Live.
В Classic ручная запись ждёт нажатия, тапа, отпускания или лимита 60 секунд.

| Действие | Что происходит |
|---|---|
| **KEY** коротко | начать запись; ещё раз (или тап) отправить фразу; в GPT Live — завершить разговор |
| **KEY** зажать | в Classic говорите и отпустите, чтобы отправить; в GPT Live отпускание не завершает разговор |
| **KEY** во время ответа | прервать ответ и начать запись; в GPT Live — завершить разговор |
| **BOOT** коротко | вернуться на предыдущий экран; на основном экране закрыть текст; на погашенном — только разбудить |
| **BOOT** удерживать 0,8 с | открыть или закрыть меню |
| **PWR** коротко | выключить или включить экран, пока Кубик работает; выключенный Кубик не включает |
| **PWR** 2 с | выключить Кубик; из выключенного состояния включить снова тем же удержанием |
| **PWR** 4 с | аппаратное выключение, если Кубик завис; включение — снова удержание **PWR** около 2 с |

Выключенный Кубик не отвечает на сеть, KEY, BOOT и касание. Подключение USB плата может включить сама: у контроллера питания нет отдельного запрета на это.

В меню (открывается удержанием **BOOT**): два ползунка, громкость и яркость (тянуть пальцем), крупные **Agent** и **Guide**, внизу **Wi‑Fi** (повторная настройка сети) и **Power off** (выключение с повторным тапом за 3 с). Полный сброс скрыт: пять раз коснитесь процента заряда за 4 с — появится **Reset**, затем подтвердите его повторным тапом за 3 с. Провайдеры распознавания и озвучки задаются на сервере. При громкости от 20 и доступном TTS ответ звучит; при меньшей громкости или недоступном TTS показывается текст. Вложенные экраны: короткий **BOOT** возвращает на один уровень, из корня Settings закрывает меню. В гайде возвращает на предыдущий шаг; из первого — в Settings без завершения гайда. Свайп вверх, **KEY**, долгое **BOOT** или 30 с без касаний закрывают меню. После потери известной сети автоматически предложенная настройка закрывается через две минуты без телефона (через десять минут с телефоном), когда не проверяет подключение. При первом запуске и ручном открытии такого таймера нет.

В `Agent` плитка Agent model открывает модели агента, а Voice — три режима:
STT, Realtime, GPT Live. Выберите режим: STT показывает Recognition и Speech,
нативные режимы сразу открывают один общий голосовой каталог. BOOT возвращает
на предыдущий уровень. Недоступный режим помечен Set up on your agent.
Режим и модели каждого режима сохраняются только для сопряжённого Кубика,
не меняя модель агента. Серверное `voice.mode` — начальное значение;
сохранённый выбор устройства имеет приоритет. Ключи и провайдеры задаются на host.
Некоторые провайдеры работают без выбора моделей; Refresh обновляет каталог.
`Guide` повторяет гайд. Значение ползунка появляется при касании. Для гайда время без
касания увеличено до двух минут; `Skip` сохраняет прохождение без сброса настроек.

## 16. Какие данные уходят из дома

- **Голос:** аудио идёт на ваш OpenClaw по защищённому соединению, дальше OpenClaw отправляет его провайдеру распознавания и озвучивания, который вы сами настроили. У Кубика нет ключей провайдера.
- **Cloudflare** видит трафик только в случае в (Tunnel завершает TLS).
- **NTP:** время запрашивается у `time.cloudflare.com` (UDP 123) только для адресов `wss://` (случаи в и г).
- **Микрофон:** Tess на включённом главном экране при готовом STT и связи локально
  распознаёт **Hi Tessa**, затем записывает команду и отправляет после паузы.
  Модель ищет Tessa; префикс Hi не проверяется, срабатывание без него возможно. До активации звук не передаётся агенту.
  В меню/гайде/настройке/pairing, при работе своего агента, активном ответе, TLS
  и во сне слушатель выключен. GPT Live поддерживает активацию, но выключает детектор на время включённого разговора;
  Realtime сохраняет её. Plush — только KEY.
- Больше Кубик никуда не обращается.

## 17. Обновление, сброс, отзыв, удаление

**Сети и питание.** Кубик помнит до восьми сетей 2,4 ГГц и подключается к известным точкам автоматически. Сохранение с тем же SSID обновляет профиль; пустой пароль сохраняет пароль уже известной сети. При заполненном списке выберите известную сеть либо сделайте полный сброс. На батарее с погашенным экраном, без активной работы, настройки, зарядки или USB, при наличии сохранённой Wi-Fi-сети радио проверяет связь по циклу 60 с: проверка длится до 48 с, а без подключения попытка прекращается через 20 с (остальное время остаётся для TLS и подтверждения доставки). Полученное уведомление или новая активность агента будят экран. Пока радио выключено, мгновенное удалённое пробуждение невозможно: уведомления ожидают следующего подключения в очереди сервера. При доступной ранее выбранной или видимой сохранённой сети, работающем агенте и синхронизированных часах уведомление доставляется и будит Кубик в пределах минуты.

**Hermes.** На машине с уже установленным Hermes выполните `python tools/install-hermes.py --home ~/.hermes` его Python-окружением и от пользователя сервиса. Перезапустите существующий Gateway при отсутствии активных разговоров. На Кубике введите `kubik://ДОСТУПНЫЙ-IP:18793`, одобрите совпадающий код командой `python ~/.hermes/plugins/kubik/pair.py КОД`. Штатные STT/TTS и модели настраиваются в Hermes. Отдельный host, Agent API и SSH-туннель не нужны; [полная инструкция](hermes.md).

**Свой агент.** Используйте [Agent SDK](agent-sdk.md) и его мастер ESM-адаптера; этот путь запускает отдельный host.

**Обновление.** Повторите установку плагина из нового `.tgz` и прошейте приложение по USB (разделы 3–4). Ставьте прошивку и плагин версии 0.6.2 вместе; сохранённые настройки и ключ остаются. Удалённые голосовые движки и `devices.<id>.prefs` нужно явно убрать из конфигурации перед обновлением: они больше не принимаются (см. README плагина, «Обновление конфигурации»). Выбор модели и состояние распознавания/озвучивания — в меню Agent; инструкция находится в `docs/agent-controls.md` комплекта.

**Полный сброс.** Удержите BOOT для открытия меню. Пять раз за 4 с коснитесь процента заряда в правом верхнем углу: появится `Reset`. Коснитесь его дважды за 3 с. Кубик стирает все сохранённые Wi-Fi, адрес и доверие к серверу, ключ устройства и личные настройки, затем перезагружается в настройку. Его нужно одобрить снова; прежнее разрешение на сервере отзовите. При закрытии меню пункт снова скрывается. Перепрошивка без этого сброса сохраняет настройки.

**Отзыв устройства.** Идентификатор `kubik-xxxxxx` виден в `openclaw pairing list kubik` (пока запрос ждёт), в логе Gateway (`new device kubik-xxxxxx wants to pair`) и в `openclaw channels status --probe`; последние 4 символа совпадают с именем сети настройки `KUBIK-XXXX`. Отозвать:

```bash
openclaw config set channels.kubik.devices.kubik-xxxxxx.enabled false
```

Действует через 1–2 секунды. Вернуть: `true`.

**Удаление.** Порядок важен: сначала список владельцев команд, потом плагин. Первое одобрение записало в `commands.ownerAllowFrom` строку `kubik:<идентификатор>:<отпечаток ключа>` (раздел 6). `openclaw plugins uninstall` её не удаляет, а без плагина OpenClaw не узнаёт префикс `kubik`, и слэш-команды на ваших других каналах (Telegram и т. п.) перестают выполняться. На компьютере с OpenClaw:

1. Посмотрите список:

   ```bash
   openclaw config get commands.ownerAllowFrom
   ```

2. Оставьте в нём всё, кроме строк `kubik:…`. Если там есть и ваши записи (в примере `telegram:123456789`), запишите список обратно без Кубика, подставив свои строки:

   ```bash
   openclaw config set commands.ownerAllowFrom '["telegram:123456789"]' --strict-json
   ```

   Если в списке были только `kubik:…`, удалите его целиком:

   ```bash
   openclaw config unset commands.ownerAllowFrom
   ```

   Перезапуск не нужен: канал `kubik` сам перезапустится на секунду.

3. Удалите плагин (`--dry-run` вместо `--force` только покажет, что будет удалено):

   ```bash
   openclaw plugins uninstall kubik --force
   ```

   Команда удаляет файлы плагина, его запись в настройках и раздел `channels.kubik` (имена устройств, отзывы устройств).

4. Перезапустите Gateway: `openclaw gateway restart` (Docker: `docker compose restart openclaw-gateway`). После этого Кубик не подключится: он покажет ошибку соединения.

Остаётся на диске (можно не трогать): ключ TLS слушателя в папке `kubik` каталога состояния OpenClaw (по умолчанию `~/.openclaw/kubik`, в Docker `$OPENCLAW_CONFIG_DIR/kubik`) и одобрения устройств в хранилище сопряжений OpenClaw: у `openclaw pairing` есть только `list` и `approve`, отзывать одобрения после удаления плагина нечем. Папку `kubik` можно удалить, если плагин больше не понадобится. Если позже поставите плагин снова, одобренные Кубики останутся одобренными, а прежний ключ TLS сохранит закрепление. Перед `openclaw channels add` тогда выполните `openclaw plugins enable kubik`: после удаления OpenClaw помнит запись `plugins.entries.kubik.enabled: false`, и без этого `channels add` отвечает `Unknown channel "kubik"`.

## 18. Известные ограничения

- **Нет шифрования флеша и NVS.** Тот, кто получит физический доступ к плате, может прочитать закрытый ключ Кубика и пароль вашего Wi-Fi. Если плата потеряна или украдена: отзовите устройство (выше) и смените пароль Wi-Fi.
- Экран Кубика только на английском.
- Прогон агента после прерывания речи не отменяется, он продолжается в фоне.
- Один Кубик — одно соединение; новое вытесняет старое.
- Первое подключение по интернету (случай б) — «доверие при первом обращении», см. раздел 9.
- Обновления прошивки по воздуху нет, только по USB (раздел 17).
- Постоянный Tunnel из комплекта — только для Linux с systemd; на macOS и Windows этот вариант вручную и не поддерживается.
- Без домена, Tailscale и публичного адреса до OpenClaw за домашним роутером нельзя достучаться снаружи домашней сети (раздел 2).
- Docker и команды Windows (разделы 12 и 13) не проверялись на реальных системах.
- Сеть настройки `KUBIK-…` защищена паролем из 8 цифр, а страница настройки открывается по HTTP. Сосед в радиусе Wi-Fi, записавший ваше подключение, может подобрать этот пароль и увидеть введённый пароль вашего Wi-Fi. Сеть живёт только несколько минут и каждый раз с новым паролем; настраивайте Кубик дома, а не в людном месте.

## Громкость речи и интерфейса

Основной ползунок Settings регулирует речь агента. Удерживайте его 0,8 секунды
без движения: Sound показывает отдельные Speech и Interface. Короткий BOOT
возвращает в Settings. Speech действует на STT, Realtime и GPT Live; Interface
на звуки интерфейса и персонажа. Ноль заглушает только выбранную группу.
Оба значения сохраняются при закрытии Settings и переживают перезапуск.
После обновления Interface наследует прежнюю громкость. Полный сброс задаёт 70
для обеих групп. Порог голосового ответа 20 относится только к Speech.
Речь больше не ослабляется общей шкалой кодека; её отдельное усиление ограничивает пики.

### Сетевые данные устройства

Settings → Status показывает текущий IP, шлюз и DNS на странице Network.
Свайп или тап по нижней подсказке открывает Device с Wi-Fi MAC и DHCP-именем,
затем Agent с адресом сервера и состоянием соединения. BOOT возвращает.
Для поиска Кубика в роутере сверяйте MAC: роутер может не показывать DHCP-имя.
Адреса 10.x.x.x — обычные локальные адреса; это не доказательство связи с Mac.

DHCP-имя устройства — `kubik-xxxxxx`: английское название и постоянный суффикс
из аппаратного MAC, свой для каждого устройства. Роутер может показывать производителя Espressif
вместо имени. IP назначает DHCP-сервер; для постоянного адреса закрепите аренду
за Wi-Fi MAC Кубика в настройках роутера. Смена IP не означает смену MAC.
